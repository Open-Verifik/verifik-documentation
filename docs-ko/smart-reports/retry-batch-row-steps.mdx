`SmartBatch`의 단일 행(`rowIndex`)에서 특정 `sequences`만 지우고 다시 큐에 넣어, 다른 모든 단계의 저장된 출력과 다른 모든 행은 그대로 유지합니다. `rowIndex`와 `sequences`는 모두 필수입니다.

배치, 대상 행, 기반 `FeatureRunner` 실행 또는 실행 항목이 현재 처리 중인 경우 서버는 `409 Conflict`로 요청을 거부합니다(`batch_is_processing`, `row_is_processing`, `run_is_processing`, `item_is_processing`).

### 엔드포인트

```text
POST https://api.verifik.co/v2/smart-batches/{id}/retry-steps
```

클라이언트별 `Authorization: Bearer <VERIFIK_JWT>`를 사용하여 Smart-Agent 프록시(`https://ai.verifik.co/v2/smart-batches/{id}/retry-steps`)를 통해서도 호출할 수 있습니다. 공유 x402 실행은 `403 Forbidden`으로 차단됩니다.

### 헤더

| 이름 | 값 | 설명 |
| ---- | -- | ---- |
| `Content-Type` | `application/json` | 요청 페이로드 형식. |
| `Authorization` | `Bearer <VERIFIK_JWT>` | 클라이언트 범위 JWT (`authUser.clientId`). |

### 매개변수

| 이름 | 타입 | 필수 | 설명 |
| ---- | ---- | ---- | ---- |
| `id` | string | 예 | `SmartBatch` ObjectId. |

### 본문

| 이름 | 타입 | 필수 | 설명 |
| ---- | ---- | ---- | ---- |
| `rowIndex` | integer | 예 | 부분 재시도할 행의 `0` 기반 인덱스(`>= 0`). |
| `sequences` | integer[] | 예 | 해당 행에서 지우고 다시 실행할 단계 시퀀스 번호(`>= 0`, 최소 `1`개, 최대 `200`개 항목). |

알 수 없는 본문 키나 누락된 필수 필드는 Joi 검증에 의해 `409 MissingParameter`로 거부됩니다.

### 참고

- 저장된 `results`와 `errors`는 `rowIndex`의 지정된 `sequences`에 대해서만 지워지며, 다른 모든 단계 시퀀스의 결과는 그대로 유지됩니다.
- 가능한 `409 Conflict` 사유는 `batch_is_processing`, `row_is_processing`, `run_is_processing`, `item_is_processing`입니다.
- 유효하지 않거나 빈 단계 시퀀스 참조를 전달하면 `400 BadRequest` (`retry_steps_invalid`)가 반환됩니다.
- 배치 전체에서 실패했거나 부분 완료된 전체 행을 재시도하려면 [실패한 Smart Batch 행 재시도](/verifik-ko/smart-reports/retry-failed-batch-rows)를 사용하세요.
