클라이언트 계정이 소유한 기존 `BatchConfiguration`을 수정합니다. 변경하려는 필드만 전송하세요. 생략된 필드는 현재 값을 유지합니다.

`steps`가 제공되면 서버는 누락된 `sequence` 값을 `index + 1`로 정규화하고 `retryDelayBaseSeconds`(`>= 1`)와 `timeoutSeconds`(`>= 5`)의 범위를 제한합니다. `notification`을 수정하면 연결된 Verifik Webhook이 자동으로 동기화되며, `executor`를 변경하면 종료 상태가 아닌 하위 배치에 새 실행기가 전파됩니다. 구성을 수정해도 조회가 실행되지 않으며 크레딧이 소비되지 않습니다.

### 엔드포인트

```
PUT https://api.verifik.co/v2/batch-configurations/{id}
```

클라이언트별 `Authorization: Bearer <VERIFIK_JWT>` 헤더를 사용하여 Smart-Agent 프록시(`https://ai.verifik.co/v2/batch-configurations/{id}`)에서도 호출할 수 있습니다. 공유 x402 실행은 `403 Forbidden`으로 차단됩니다.

### 헤더

| 이름 | 값 |
| ---- | -- |
| Content-Type | `application/json` |
| Authorization | `Bearer <VERIFIK_JWT>` |

토큰은 **클라이언트 JWT**여야 합니다. 자격 증명이 누락되었거나 유효하지 않으면 `401 Unauthorized`가 반환됩니다.

### 매개변수

| 이름 | 타입 | 필수 | 설명 |
| ---- | ---- | ---- | ---- |
| `id` | string | 예 | 수정할 `BatchConfiguration` ObjectId. |

### 본문

모든 본문 필드는 선택 사항입니다. 수정하려는 속성만 포함하세요.

| 이름 | 타입 | 필수 | 설명 |
| ---- | ---- | ---- | ---- |
| `name` | string | 아니요 | 구성의 표시 이름. 앞뒤 공백이 제거되며 최대 `150`자입니다. |
| `description` | string | 아니요 | 워크플로우에 대한 선택적 요약. 최대 `800`자. |
| `country` | string | 아니요 | 국가 범위. 서버에서 공백을 제거하고 대문자로 변환합니다. |
| `steps` | object[] | 아니요 | 순서가 지정된 단계 배열을 대체합니다. 누락된 `sequence`는 기본값 `index + 1`이 되며 `retryDelayBaseSeconds`는 `>= 1`로, `timeoutSeconds`는 `>= 5`로 제한됩니다. |
| `inputFormat` | string | 아니요 | 기본 입력 형식: `csv`, `jsonl` 또는 `xlsx`. |
| `outputFormat` | string | 아니요 | 기본 출력 형식: `csv`, `jsonl` 또는 `xlsx`. |
| `mergeStrategy` | string | 아니요 | 단계 실행 전략: `sequential`, `parallel-independent` 또는 `parallel-with-fallback`. |
| `notification` | object | 아니요 | 완료 알림 설정(`webhookUrl` 및 `emailOnCompletion`). `webhookUrl`이 설정되면 활성 Verifik Webhook이 자동으로 동기화됩니다. |
| `scheduleExpression` | string | 아니요 | 자동 실행을 위한 스케줄 표현식. |
| `preferredReportTemplate` | string | 아니요 | 이 구성에 연결된 `SmartReportTemplate` ObjectId. |
| `visitaFlow` | object | 아니요 | 단계 체이닝을 정의하는 시각적 노드 그래프(`{{results.N.field}}` 표현식은 파생된 입력 스키마의 수동 입력에서 제외됨). |
| `isActive` | boolean | 아니요 | 구성의 활성 여부. |
| `executor` | string | 아니요 | 실행 대상: `queue`, `featureRunner` 또는 `browser`(`featureRunner`는 `browser`로 저장됨). 변경 시 종료 상태가 아닌 하위 배치를 동기화합니다. |

### 참고

- `steps`를 전송하면 구성의 전체 `steps` 배열이 교체됩니다. 개별 단계를 부분 수정(patch)하지는 않습니다.
- `steps` 내부에서 누락된 `sequence` 값은 `index + 1`로 정규화되며 `retryDelayBaseSeconds`는 `>= 1`로, `timeoutSeconds`는 `>= 5`로 제한됩니다.
- `executor`를 변경하면 이 구성에 속한 종료 상태가 아닌 하위 배치가 동기화됩니다.
- 누락되었거나 다른 클라이언트의 ID는 `404` (`not_found`)를 반환하며, Mongoose 스키마 검증 오류는 `422` (`UnprocessableEntity`)를 반환합니다.
