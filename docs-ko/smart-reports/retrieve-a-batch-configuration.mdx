ObjectId(`{id}`)로 단일 `BatchConfiguration`을 조회합니다. 조회는 인증된 클라이언트 JWT 범위로 제한되며, 계정의 `ClientFeature` 가격 정보로 보강되고 채워진 `steps.appFeature` 세부 정보를 반환합니다.

일치하는 구성이 없거나 ID가 다른 클라이언트 계정에 속한 경우 엔드포인트는 `data: null`과 함께 HTTP `200`을 반환합니다. 구성을 읽어도 조회가 실행되지 않으며 크레딧이 소비되지 않습니다.

### 엔드포인트

```
GET https://api.verifik.co/v2/batch-configurations/{id}
```

클라이언트별 `Authorization: Bearer <VERIFIK_JWT>` 헤더를 사용하여 Smart-Agent 프록시(`https://ai.verifik.co/v2/batch-configurations/{id}`)에서도 호출할 수 있습니다. 공유 x402 실행은 `403 Forbidden`으로 차단됩니다.

### 헤더

| 이름 | 값 |
| ---- | -- |
| Content-Type | `application/json` |
| Authorization | `Bearer <VERIFIK_JWT>` |

토큰은 **클라이언트 JWT**여야 합니다. 자격 증명이 누락되었거나 유효하지 않으면 `401 Unauthorized`가 반환됩니다.

### 매개변수

| 이름 | 타입 | 필수 | 설명 |
| ---- | ---- | ---- | ---- |
| `id` | string | 예 | 생성, 복제 또는 목록 조회에서 얻은 `BatchConfiguration` ObjectId. |

### 참고

- `{id}`가 존재하지 않거나 다른 클라이언트 계정에 속한 경우, 이 엔드포인트는 `{ "data": null }`과 함께 HTTP `200`을 반환합니다.
- 연동 코드에서 `data`의 속성을 읽기 전에 `data !== null`인지 확인하세요.
- 구성에 대해 확인된 필수/선택 입력과 `exampleInput` 페이로드를 검사하려면 [구성 입력 스키마 조회](/verifik-ko/smart-reports/retrieve-configuration-input-schema)를 호출하세요.
