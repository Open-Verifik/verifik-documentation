# 크레딧 청구 및 소비 정책

**API 조회 청구 규칙과 동적 가격**

**버전 1.0 | 게시일: 2026년 10월 26일**

이 정책은 여기에 적힌 서비스에 적용되는 일반적인 청구 및 크레딧 소비 규칙을 설명합니다. 요율과 개별 조건은 각 고객과 명시적으로 합의한 내용입니다. 이 정책의 변경을 게시하는 것만으로 이미 발효 중인 계약이 일방적으로 변경되지는 않습니다.

## 1. smartCHECK(DB Screening) 청구 체계

### 1.1. 일반 청구 규칙

청구 체계는 정부 데이터베이스를 조회하는 smartCHECK(DB Screening) 솔루션에 적용됩니다.

**일반 규칙.** HTTP 200 응답은 청구됩니다. HTTP 403, 412, 422, 500, 시간 초과, HTTP 409(출처 불가와 연결 장애를 포함)는 청구되지 않습니다. HTTP 404는 제1.2조에 명시된 경우에만 청구됩니다.

| 청구 | 미청구 |
| --- | --- |
| 200 | 403 |
|  | 404 |
|  | 409 |
|  | 412 |
|  | 422 |
|  | 500 |
|  | 시간 초과 |

콜롬비아 밖의 엔드포인트는 HTTP 404로 청구되지 않습니다. 제1.2조에 포함되지 않은 엔드포인트도 HTTP 404로 청구되지 않습니다.

### 1.2. 콜롬비아: HTTP 404 청구 예외

이 조는 smartCHECK에서 HTTP 404 요금의 유일한 근거입니다. 아래 경로는 모두 콜롬비아 API입니다. 시간 초과와 HTTP 409 출처 장애는 청구되지 않습니다.

**RUNT**(응답 코드가 `NotFound`인 HTTP 404만). HTTP 409 응답(예를 들어 출처가 서비스 불능이거나 RUNT 워커를 사용할 수 없는 경우)은 청구되지 않습니다.

| 제품 이름 | 경로 |
| --- | --- |
| 콜롬비아 RUNT 운전자 조회 | `GET /v2/co/runt/conductor` |
| 콜롬비아 RUNT 운전자 조회(v3) | `GET /v3/co/runt/conductor` |
| 콜롬비아 RUNT 차량 조회 | `GET /v2/co/runt/vehiculo` |
| 콜롬비아 RUNT 차량 전체 기록 | `GET /v2/co/runt/vehiculo-completo` |
| 콜롬비아 RUNT 차량 SOAT | `GET /v2/co/runt/vehiculo-soat` |
| 콜롬비아 RUNT 번호판별 차량 | `GET /v2/co/runt/vehicle-by-plate` |
| 콜롬비아 RUNT VIN별 차량 | `GET /v2/co/runt/vehicle-by-vin` |
| 콜롬비아 RUNT 번호판별 차량(간소화) | `GET /v2/co/runt/vehicle-by-plate-simplified` |
| 콜롬비아 RUNT 번호판만으로 차량 | `GET /v2/co/runt/vehicle-by-plate-only` |

**사회보장 가입.** 다음 경로의 HTTP 404는 모두 청구 대상이며, 메시지가 잘못된 발급일을 가리키는 경우도 포함됩니다. HTTP 409를 반환하는 연결 장애는 청구되지 않습니다.

| 제품 이름 | 경로 |
| --- | --- |
| 콜롬비아 사회보장 가입 | `GET /v2/co/afiliaciones` |

**SIBGA 차량 가치 평가**(응답 코드가 `NotFound`인 HTTP 404만).

| 제품 이름 | 경로 |
| --- | --- |
| 콜롬비아 SIBGA 차량 가치 평가 | `GET /v2/co/sibga/valuation` |

**콜롬비아 시민권 카드(cédula).** 메시지가 `CEDULA NO EXISTE`인 HTTP 404만 유효성 요율로 청구됩니다. 다음 경로의 그 밖의 HTTP 404는 청구되지 않습니다. `GET`/`POST /v2/co/cedula/vigencia`는 자신의 HTTP 404 응답을 청구하지 않습니다.

| 제품 이름 | 경로 |
| --- | --- |
| 콜롬비아 시민권 카드 조회 | `GET` / `POST /v2/co/cedula` |

**HTTP 404로 청구되지 않는 경우:** 콜롬비아의 그 밖의 RUNT 경로(소유자 조회를 포함), 콜롬비아 밖의 모든 엔드포인트, 이 조에 없는 모든 경로. 얼굴 라이브니스는 라이브니스 실패에 대해 HTTP 409를 청구할 수 있으며 HTTP 404로는 청구되지 않습니다. smartBatch는 HTTP 404를 행을 성공으로 표시하는 데만 사용하며 해당 응답에 대해 크레딧을 청구하지 않습니다.

## 2. smartCHECK의 동적 쿼리

동적 쿼리의 기술적 설명은 [서비스 수준 계약 제5조](/verifik-ko/legal/service-level-agreement#dynamic-query)에 있습니다. 이 정책은 그 설명을 반복하지 않습니다.

청구 목적상, 호환 엔드포인트에서 기본 출처가 만족스러운 결과를 내지 않으면 Verifik은 대체 정보 출처를 자동으로 순차 조회할 수 있습니다. 동적 쿼리는 연속 조회가 필요하므로 응답 시간이 늘어날 수 있습니다. Verifik은 서비스를 최적화하기 위해 사용하는 출처를 수정, 우선순위 조정 또는 교체할 수 있습니다. 이는 합의된 요율의 일방적 변경을 허용하지 않습니다.

## 3. 콜롬비아 시민권 카드 조회의 동적 가격 {#dynamic-pricing-billing}

고객은 `GET`/`POST /v2/co/cedula` 엔드포인트를 통한 조회가, 사용된 정보 출처와 [서비스 수준 계약 제5조](/verifik-ko/legal/service-level-agreement#dynamic-query)에 설명되고 이 정책 제2조에서 가리키는 동적 쿼리로 얻은 결과에 따라 동적 가격의 적용을 받을 수 있음을 인정하고 동의합니다.

### 3.1. 표준 요율과 프리미엄 요율

표준 출처로 조회가 성공적으로 해결되면(HTTP 200) 콜롬비아 신분증 조회 서비스의 표준 요율이 적용됩니다.

표준 출처가 만족스러운 일치를 내지 못하고 동적 쿼리가 확장 또는 프리미엄 검증 출처를 통해 성공 응답(HTTP 200)을 얻으면, 고객이 표준 엔드포인트를 사용했더라도 해당 프리미엄 요율이 적용됩니다.

표준 요율과 프리미엄 요율은 각 고객과 계약 또는 양 당사자가 수락한 요율표에서 명시적으로 합의한 요율입니다.

### 3.2. 계약 요율과의 관계

`GET`/`POST /v2/co/cedula` 엔드포인트의 표준 또는 프리미엄 범주는, 적용 계약이 이 규칙을 명시적으로 포함하는 경우 이 정책에 따라 정합니다. 조회당 일반 요율과 충돌하면, 계약이 그렇게 정한 경우에만 범주 선택에 관한 특정 규칙이 우선합니다.

이 규칙은 Verifik이 이미 합의된 요율의 금액을 일방적으로 변경할 권한을 주지 않습니다.

### 3.3. 불만족 응답과 청구 예외

HTTP 404 응답은 제1.2조의 예외와 그곳에 정한 요율에 따라서만 청구됩니다.

그 밖의 비청구 응답은 제1.1조를 따릅니다.

### 3.4. 청구 투명성 {#include-cost}

고객은 적격 요청에서 `includeCost=true` 매개변수를 사용하여 청구된 크레딧 정보를 받을 수 있습니다.

API 요청 이력에서 소비 기록과 해당 청구 조정, 동적 쿼리로 프리미엄 요율이 적용된 경우를 조회할 수 있습니다.

### 3.5. 직접 프리미엄 조회

`/v2/co/cedula/premium` 엔드포인트를 통해 직접 수행한 조회는 자동 상향 메커니즘의 사용 여부와 관계없이 해당 프리미엄 요율의 적용을 받습니다.

이 조의 규정은 여기에 적힌 엔드포인트에만 적용되며, 그 밖에 계약된 서비스의 요율이나 청구 조건을 변경하지 않습니다.

API 세부 사항은 [콜롬비아 국민 신분증 확인(기본)](/verifik-ko/identity-validation/colombia/colombian-citizen)을 참조하십시오.

**효력과 개별 조건.** 차이가 있으면 상업 계약에서 명시적으로 수락한 경제 조건이 우선합니다. 다만 그 계약이 구체적으로 포함하는 동적 가격 예외는 제외합니다.
