認証済みクライアントに Check List を作成します。`name` は必須です。国、ドメイン、フィーチャーコードは作成時は任意です。あとから [チェックリストを更新](/verifik-ja/check-list/update-a-check-list) でサービスを追加できます。

リストの保存は照会を実行せず、クレジットも消費しません。Smart-Agent では作成後にダッシュボードに戻ります。この API は新しいドキュメントをすぐ返します。

### Endpoint

```
POST https://api.verifik.co/v2/check-lists
```

JWT 上のクライアントが所有するリストを作成します。応答の `data` オブジェクトには `_id` が含まれます。後の GET、PUT、DELETE のために保存してください。既定の `status` は `draft` です。

### Headers

| Name          | Value              |
| ------------- | ------------------ |
| Content-Type  | `application/json` |
| Authorization | `Bearer <token>`   |

トークンは **クライアント JWT** である必要があります。`clientId` のないトークンは `403` を返します。

### Body

| Name           | Type     | Required | Description                                                                 |
| -------------- | -------- | -------- | --------------------------------------------------------------------------- |
| `name`         | string   | Yes      | 表示名。トリム済み、1〜150 文字。                                    |
| `countries`    | string[] | No       | 事業国名（例: `Colombia`）。重複は削除されます。既定は `[]`。 |
| `domains`      | string[] | No       | 任意のタブ: `people`、`vehicles`、`businesses`。既定は `[]`。            |
| `featureCodes` | string[] | No       | リストに保存する AppFeature の `code`。既定は `[]`。                 |
| `status`       | string   | No       | `draft`（既定）または `active`。整理用ラベルのみで、どちらも同じです。   |

不明な `featureCodes` は失敗します。国が `countries` と一致しないサービスは、そのサービスが世界向けであるか `countries` が空でない限り失敗します。

### Notes

- 必須フィールドは `name` だけです。空のリストを作成して、あとから `featureCodes` を追加できます。
- 国は送ったとおりに保存されます（例: `Colombia`）。ISO コードではありません。
- `status` はサーバーの動作を変えません。下書きも有効も同じように動きます。
- 不明な `domains` の値はバリデーションに失敗します。許可される値: `people`、`vehicles`、`businesses`。
- リストの作成はクレジットを消費しません。保存したサービスの実行は通常のカタログ呼び出しです。
- チェックリスト実行エンドポイントはありません。[Check List](/verifik-ja/check-list) と [SmartBatch](/verifik-ja/smart-batch) を見てください。
