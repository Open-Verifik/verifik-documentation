id で Check List を 1 件読み込みます。リストは JWT 上のクライアントに属している必要があります。無効な ObjectId、存在しないリスト、他のクライアントのリストは `404` を返します。

この呼び出しは照会を実行せず、クレジットも消費しません。ドキュメントの `featureCodes` を使って、各カタログ API を自分で呼び出してください。

### Endpoint

```
GET https://api.verifik.co/v2/check-lists/{id}
```

保存済みリストを返します: `name`、`countries`、`domains`、`featureCodes`、`status`。これらのコードを、対応する SmartCheck / カタログ URL と一緒に使います。このパスにチェックリスト実行アクションはありません。

### Headers

| Name          | Value              |
| ------------- | ------------------ |
| Content-Type  | `application/json` |
| Authorization | `Bearer <token>`   |

トークンは **クライアント JWT** である必要があります。`clientId` のないトークンは `403` を返します。

### Parameters

| Name | Type   | Required | Description                          |
| ---- | ------ | -------- | ------------------------------------ |
| `id` | string | Yes      | 作成または一覧から得た Check List の ObjectId。 |

### Notes

- 無効な ObjectId と他のクライアントのリストは、どちらも `404`（`check_list_not_found`）です。
- 応答にはホスト型の再開 URL やバッチ URL は含まれません。Check List は組み合わせだけを保存します。
- フィールドを変えるには [チェックリストを更新](/verifik-ja/check-list/update-a-check-list) を使います。削除するには [チェックリストを削除](/verifik-ja/check-list/delete-a-check-list) を使います。
- `featureCodes` のコードを実行するのは通常のカタログ呼び出しで、そこでクレジットが消費されます。
