# データ保持

アカウント、プロジェクト、プロジェクトフローの設定が、文書画像、文書検証とともに保存された抽出フィールド、顔画像を Verifik がどのくらい保持するかを決めます。ポリシーは新しいレコードが作られたときに刻まれます。その後の変更は、すでに存在するレコードを書き換えません。

画像を削除しても、請求記録、クレジットの引き落とし、利用履歴はそのまま残ります。

## モード

| モード | 効果 |
| --- | --- |
| `store` | レコードを保持します。`retentionHours` を 0 より大きい数にすると、その時間の後に削除対象になります。`retentionHours` を省略すると期限なく保持します。 |
| `ephemeral` | Webhook があるときは Webhook の保持時間が終わった時点で、Webhook がないときは次の削除実行で削除対象になります。`retentionHours` は無視されます。 |
| `none` | 文書画像と保存された抽出フィールドは `ephemeral` と同じタイミングです。このモードの顔画像は書き込まれません。SmartEnroll の応答はホストされた URL を省き、`hasFrontImage` または `hasBackImage` を返します。 |

SmartEnroll の文書スキャンでは、`retentionHours` を含む `store` でも 24 時間の保持、Webhook がある場合はその保持を使います。時間のない `store` はその画像を保持します。

`ephemeral` と `none` は削除のタイミングが同じです。顔画像と、SmartEnroll がホストされた URL を返すかどうかで違います。

## このポリシーが適用する種類

| キー | 対象 |
| --- | --- |
| `documentImages` | 文書検証の表面と裏面の写真。`url` と `backUrl` の先にあるホストされたファイルを含みます。 |
| `ocrExtraction` | その検証に保存された抽出結果。 |
| `faceImages` | 登録またはログインのために保存されたセルフィーと文書の顔画像。 |

各キーに `mode` を設定してください。最上位の `mode` が `none` のとき、空のキーへコピーされます。最上位の `store` または `ephemeral` はそれらのキーを置き換えません。必要なキーをすべて書くリクエストが確実です。

## このポリシーの外に残るもの

次の記録は独自の保存ルールに従います。保持モードを保存しても、これらは削除されません。

- 文書のライブネス写真
- ライブネスのスコアとセッション結果
- Webhook の本文。ペイロードに載る抽出結果を含みます
- API 応答ログ
- Smart Access が再訪した人物を照合するときに使う生体テンプレートと顔コレクション
- Human Auth の暗号化された資格情報、ゼロ知識の生成物、ライブネス動画
- Human Auth の資格情報を置く保存場所
- 保持スタンプが存在する前に作られた文書検証と本人画像

ホストされた文書画像は通常の URL を使います。URL はそのファイルが削除されるまで有効です。画像 URL はすべて機密として扱ってください。

## 優先順位

有効なポリシーは次の順で決まります。

1. **アカウント。** クライアント設定に保存されたポリシー。
2. **プロジェクト。** プロジェクトの `dataRetention` が、アカウントのうちそのオブジェクトが指定したフィールドを置き換えます。
3. **プロジェクトフロー。** フローの `dataRetention` が、プロジェクトのうちそのオブジェクトが指定したフィールドを置き換えます。

ある層がフィールドを省略すると、より広い値が残ります。何も設定しない場合、適用される種類はすべて期限のない `store` で、Webhook の保持は 24 時間です。

保存したポリシーが各実行インスタンスに反映されるまで、およそ 1 分かかることがあります。

## Webhook の保持

`webhookHoldHours` は 24 から 72 の整数です。既定値は 24 です。

Webhook があるとき、`none` と `ephemeral` のレコードは配信が終わるよう、少なくともこの時間残ります。その登録への Webhook が配信されたあと、これらのモードの画像は後の削除実行で取り除かれることがあります。ペイロード内の画像 URL は、その配信のあと使えなくなることがあります。Webhook を処理する間に、まだ必要な画像をコピーしてください。

SmartEnroll の終端イベントは `onboarding_app_registration_completed`、`onboarding_app_registration_needs_manual_verification`、`onboarding_app_registration_completed_without_kyc`、`onboarding_app_registration_failed` です。

保持ポリシーは Webhook 本文を伏せません。ペイロードには抽出結果の全体が含まれることがあります。

## 削除が取り除き、伏せ、残すもの

文書検証が削除されるとき:

| 操作 | フィールド |
| --- | --- |
| 除去 | ホストされた画像ファイル。`url`、`backUrl`、ファイル一覧が空になります。 |
| マスク | 保存された抽出結果と `fullName`。 |
| 平文のまま | `documentNumber`、名、姓、リクエストパラメータ、検証に保存されたスクリーニング結果。 |
| 行は残る | 状態、種類、`createdAt`。この行を読む利用回数には引き続き含まれます。 |

顔画像の削除は、保存された画像のバイトを消します。

抽出全体の暗号化されたコピーは、スキャンから 30 日後に除去されます。見えている保存フィールドがすでにマスクされていても同じです。

クレジットの引き落としはスキャンが成功したときに記録されます。削除は請求記録と利用履歴を残し、引き落としを戻しません。

文書検証またはアプリ登録を削除すると、保存された画像ファイルと検証の行が消えます。その行から作った利用履歴は、その削除の分だけ減ります。削除ジョブは行を残します。

## 削除が実行されるとき

レコードは `retention.purgeAfter` で削除対象になります。スケジュールされた削除は、対象レコードをおよそ 15 分ごとに取り除きます。実際の削除は次に成功した実行で起きるため、ファイルは `purgeAfter` のあと少し残ることがあります。1 回の実行が扱う件数には上限があります。待ち行列が大きいと複数回の実行が必要です。

手動消去のエンドポイントはありません。ポリシーオブジェクトの `allowManualDelete` はポリシーとともに保存されるだけで、別の消去呼び出しを開きません。

## ポリシーは新しいレコードに適用されます

スタンプはレコード作成時に書かれます。アカウントにすでにあるレコードは、自分のスタンプを保ちます。スタンプのないレコードはそのまま残ります。アカウントを `none` に切り替えても、その変更より前に保存された履歴は残ります。

## プロジェクトのないスキャン

`POST /v2/ocr/scan-prompt` と `POST /v2/ocr/scan-agent` は、呼び出しがプロジェクトに結び付いていないとき、この規則に従います。

- 画像はホストされたストレージへアップロードされません。
- 応答の `url` と `backUrl` は、送った画像の `data:` URI です。その応答に属します。抽出結果を保存し、写真がまだ必要なら画像のコピーを自分で保持してください。
- 応答本文には抽出結果の全体があります。
- 保存される検証行は、マスクされた抽出結果とマスクされた `fullName` を持ちます。その行の `documentNumber` は平文のままです。
- 抽出全体の暗号化されたコピーは 30 日後に除去されます。

SmartEnroll の文書スキャンはアプリ登録に結び付き、アカウント、プロジェクト、フローから決めたポリシーを使います。応答にはマスクされていない抽出結果があります。`ocrExtraction` が `none` のとき、保存された行はマスクされます。`none` と `ephemeral` では、応答はホストされた URL を省きます。

## Smart Access

Smart Access のログインフロー（`login` プロジェクトフロー）は、ログインのセルフィーに保持を刻みます。

- `faceImages` が `none` のとき、ログインのセルフィーは保存されません。
- `ephemeral` は次の削除実行までセルフィーを保存します。ログインフローは Webhook 保持なしで刻まれます。
- `store` はセルフィーを保持します。`retentionHours` があるときはその時間です。

再訪した人物の照合には生体テンプレートと顔コレクションを使います。このポリシーを変えても、そのテンプレートは残ります。ログインのライブネス結果とログインの Webhook 本文も残ります。

## Human Auth

Human Auth のオンボーディング中に作られた文書検証は、上の SmartEnroll の規則を使います。

Human Auth のプロジェクトは `faceImages` を `none` に固定できます。そのモードではセルフィーは保存されず、保存されたセルフィーを読む文書とセルフィーの比較は実行されません。

ライブネス動画、ゼロ知識の生成物、保存ステップが作る暗号化された資格情報は、それぞれの規則に従います。その資格情報の保存場所を選ぶことは、このポリシーとは別です。

## `dataRetention` オブジェクト

`PUT /v3/projects/{id}` にこのオブジェクトを送ります。`null` を送ると、アカウントのポリシーを再び継承します。

プロジェクトフローに同じ形があると、そのフローで作られたレコードについてプロジェクトを置き換えます。

```json
{
  "dataRetention": {
    "mode": "none",
    "webhookHoldHours": 24,
    "types": {
      "documentImages": { "mode": "none" },
      "ocrExtraction": { "mode": "none" },
      "faceImages": { "mode": "store", "retentionHours": 72 }
    }
  }
}
```

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `mode` | `store`、`ephemeral`、`none` | アカウントまたは上書きの基準。各種類も設定してください。 |
| `webhookHoldHours` | 整数、24–72 | Webhook があるときの最短保持。既定値 24。 |
| `types.documentImages.mode` | モード | 文書の写真。 |
| `types.documentImages.retentionHours` | 数値または省略 | その種類が `store` で数値が 0 より大きいときに使います。SmartEnroll の文書画像では無視されます。 |
| `types.ocrExtraction` | 同じ形 | 保存された抽出結果。 |
| `types.faceImages` | 同じ形 | セルフィーと文書の顔画像。`none` ではセルフィーは書き込まれません。 |

保存されたポリシーに他の種類のキーがあることがあります。削除はそれらを適用しません。
