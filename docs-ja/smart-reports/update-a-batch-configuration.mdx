クライアントアカウントが所有する既存の `BatchConfiguration` を更新します。変更したいフィールドのみを送信してください。省略されたフィールドは現在の値を保持します。

`steps` を指定すると、サーバーは不足している `sequence` 値を `index + 1` に正規化し、`retryDelayBaseSeconds`（`>= 1`）および `timeoutSeconds`（`>= 5`）をクランプします。`notification` を更新すると関連付けられた Verifik Webhook が自動的に同期され、`executor` を変更すると終了状態でない子バッチにも新しい executor が伝播されます。設定を更新しても照会は実行されず、クレジットも消費されません。

### エンドポイント

```
PUT https://api.verifik.co/v2/batch-configurations/{id}
```

クライアント単位の `Authorization: Bearer <VERIFIK_JWT>` ヘッダーを使用することで、Smart-Agent プロキシ（`https://ai.verifik.co/v2/batch-configurations/{id}`）経由でもアクセスできます。共有 x402 実行は `403 Forbidden` でブロックされます。

### ヘッダー

| 名前 | 値 |
| ---- | ----- |
| Content-Type | `application/json` |
| Authorization | `Bearer <VERIFIK_JWT>` |

トークンは **クライアント JWT** である必要があります。認証情報がないか無効な場合は `401 Unauthorized` を返します。

### パラメータ

| 名前 | 型 | 必須 | 説明 |
| ---- | ---- | ---- | ----------- |
| `id` | string | はい | 更新する `BatchConfiguration` の ObjectId。 |

### リクエストボディ

すべてのボディフィールドは任意です。更新したいプロパティのみを含めてください。

| 名前 | 型 | 必須 | 説明 |
| ---- | ---- | ---- | ----------- |
| `name` | string | いいえ | 設定の表示名。トリム済み、最大 `150` 文字。 |
| `description` | string | いいえ | ワークフローの任意の概要。最大 `800` 文字。 |
| `country` | string | いいえ | 対象国スコープ。サーバー側でトリムおよび大文字化されます。 |
| `steps` | object[] | いいえ | 順序付きステップ配列を置き換えます。不足している `sequence` は既定で `index + 1` となり、`retryDelayBaseSeconds` は `>= 1` に、`timeoutSeconds` は `>= 5` にクランプされます。 |
| `inputFormat` | string | いいえ | 既定の入力形式: `csv`、`jsonl`、または `xlsx`。 |
| `outputFormat` | string | いいえ | 既定の出力形式: `csv`、`jsonl`、または `xlsx`。 |
| `mergeStrategy` | string | いいえ | ステップ実行戦略: `sequential`、`parallel-independent`、または `parallel-with-fallback`。 |
| `notification` | object | いいえ | 完了通知設定（`webhookUrl` および `emailOnCompletion`）。`webhookUrl` を設定すると、有効な Verifik Webhook が自動的に同期されます。 |
| `scheduleExpression` | string | いいえ | 自動実行用のスケジュール式。 |
| `preferredReportTemplate` | string | いいえ | この設定にリンクする `SmartReportTemplate` の ObjectId。 |
| `visitaFlow` | object | いいえ | ステップ連鎖を定義するビジュアルノードグラフ（`{{results.N.field}}` 式は導出された入力スキーマの手動入力から除外されます）。 |
| `isActive` | boolean | いいえ | 設定が有効かどうか。 |
| `executor` | string | いいえ | 実行ターゲット: `queue`、`featureRunner`、または `browser`（`featureRunner` は `browser` として永続化されます）。変更されると終了状態でない子バッチも同期されます。 |

### 補足

- `steps` を送信すると、設定上の `steps` 配列全体が置き換えられます（個別のステップだけを部分更新するわけではありません）。
- `steps` 内で不足している `sequence` 値は `index + 1` に正規化され、`retryDelayBaseSeconds` は `>= 1`、`timeoutSeconds` は `>= 5` にクランプされます。
- `executor` を変更すると、この設定に属する終了状態でない子バッチが同期されます。
- ID が存在しないか他クライアントに属している場合は `404`（`not_found`）が返され、Mongoose のスキーマ検証エラーは `422`（`UnprocessableEntity`）が返されます。
