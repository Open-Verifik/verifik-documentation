既存の行や保存済み結果を上書きすることなく、既存の `SmartBatch` に新しい入力行を追加します。ラップされた行（`{ rowIndex?, inputData }`）とフラットな行（`{ rowIndex?, ...inputFields }`）のどちらも受け付けられ、サーバーは `maxExisting + 1` から始まる連続した行インデックスを割り当てます。

バッチが `"processing"` の間は行の追加は禁止されています（`400 batch_append_not_allowed_while_processing`）。バッチが以前に `"completed"` または `"failed"` になっていた場合、行を追加すると `status` が `"pending"` にリセットされ、`completedAt` がクリアされるため、新しい行を実行できるようになります。

### エンドポイント

```text
POST https://api.verifik.co/v2/smart-batches/{id}/rows/append
```

このエンドポイントは、クライアント単位の `Authorization: Bearer <VERIFIK_JWT>` を使用することで Smart-Agent プロキシ（`https://ai.verifik.co/v2/smart-batches/{id}/rows/append`）経由でもアクセスできます。共有 x402 実行は `403 Forbidden` でブロックされます。

### ヘッダー

| 名前 | 値 | 説明 |
| --------------- | ---------------------- | ---------------------------------------- |
| `Content-Type` | `application/json` | リクエストペイロード形式。 |
| `Authorization` | `Bearer <VERIFIK_JWT>` | クライアントスコープの JWT（`authUser.clientId`）。 |

### パラメータ

| 名前 | 型 | 必須 | 説明 |
| ---- | ------ | ---- | ----------- |
| `id` | string | はい | 行を追加する `SmartBatch` の ObjectId。 |

### リクエストボディ

| 名前 | 型 | 必須 | 説明 |
| ------ | -------- | ---- | ----------- |
| `rows` | object[] | はい | ラップ形式（`{ rowIndex?, inputData }`）またはフラット形式（`{ rowIndex?, ...inputFields }`）の入力行からなる空でない配列（`min 1`）。サーバーが連番の `rowIndex = maxExisting + 1` を割り当てます。 |

不明なボディキーや空の `rows` 配列は Joi バリデーションにより `409 MissingParameter` で拒否されます。

### 補足

- 行を追加してもチェックは実行されず、クレジットも消費されません。その後[Smart Batch を開始する](/verifik-ja/smart-reports/start-a-smart-batch)でバッチを開始してください。
- クライアントが指定した `rowIndex` はすべて無視され、`maxExisting + 1` から始まるサーバー割り当ての連番が優先されます。
- バッチが `"completed"` または `"failed"` だった場合、その `status` は `"pending"` にリセットされ、`completedAt` はクリアされます。
