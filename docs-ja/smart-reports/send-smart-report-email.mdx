PDF レポートを添付して `SmartReport` をメールで配信します。Verifik に単一行（`rowIndex`）または全行（`sendAll: true`、最大 `50` 行）の PDF をレンダリングさせることも、事前にレンダリングした `printHtml`、`pdfBase64`、または `pdfFiles` ペイロードを渡すこともできます。

メールを送信すると `SmartReport` ドキュメントに `emailDelivery` が記録され、成功時には `smart_batch_report_sent`、配信失敗時には `smart_batch_report_delivery_failed` が発火されます。

### エンドポイント

```
POST https://api.verifik.co/v2/smart-reports/{id}/send-email
```

このエンドポイントは最大 **64 MB** の JSON ペイロードを受け付けます。お客様自身のクライアント別 `Authorization: Bearer <VERIFIK_JWT>` を使用して Smart-Agent プロキシ経由の `https://ai.verifik.co/v2/smart-reports/{id}/send-email` からも利用できます。共有 x402 による実行は `403 Forbidden` でブロックされます。

### ヘッダー

| 名前 | 値 | 説明 |
| --- | --- | --- |
| `Content-Type` | `application/json` | リクエストペイロードの形式（上限 64 MB）。 |
| `Authorization` | `Bearer <VERIFIK_JWT>` | クライアント単位の JWT（`authUser.clientId`）。 |

### パラメータ

| 名前 | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `id` | string | **はい** | `SmartReport` ObjectId。 |

### ボディ

| 名前 | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `recipients` | string[] | **はい** | 有効な受信者メールアドレスの配列（最小 `1` 件）。 |
| `subject` | string | いいえ | カスタムメール件名。 |
| `language` | string | いいえ | メール文面の言語: `"en"` または `"es"`。デフォルトは `"es"`。 |
| `rowIndex` | number | いいえ | `sendAll` が有効でない場合にレンダリングして添付する 0 始まりの行インデックス。 |
| `sendAll` | boolean | いいえ | `true` の場合、最大 `50` 行（`MAX_SEND_ALL_ROWS`）を送信し、バッチに 2 行以上ある場合は 1 行につき 1 つの PDF を添付します。 |
| `engine` | string | いいえ | PDF レンダリングエンジン: `"pdfkit"` または `"puppeteer"`。 |
| `printHtml` | string | いいえ | 変換して添付する事前レンダリング済み HTML 文字列（最大 `64000000` 文字）。 |
| `pdfBase64` | string | いいえ | 直接添付する事前レンダリング済み base64 エンコード PDF 文字列（最大 `64000000` 文字）。 |
| `pdfFiles` | object[] | いいえ | 最大 `200` 件の添付オブジェクト配列（`{ filename, pdfBase64 }`）。各オブジェクトで `filename`（最大 `80` 文字）と `pdfBase64`（最大 `64000000` 文字）が必須です。 |

#### 添付ファイルとバッチ配信のルール

- **`sendAll` の上限**: バッチ内の全行送信は最大 `50` 行（`MAX_SEND_ALL_ROWS`）までサポートされています。50 行を超えると `409 Conflict`（`send_all_limit`）で失敗します。バッチに 2 行以上含まれる場合、各行が個別の PDF ファイルとして添付されます。
- **事前レンダリング済みペイロード**: 統合システム側ですでにカスタム添付ファイルをレンダリングしている場合は、`pdfFiles`（最大 `200` 件）、`pdfBase64`、または `printHtml` を指定します。破損した PDF データは `500`（`invalid_pdf`）を返し、添付ファイルが 0 件に解決されるリクエストは `409 Conflict`（`no_pdf_attachments`）を返します。
- **配信結果レスポンス**: 検証と PDF 準備が成功した後にメールトランスポートが失敗した場合、エンドポイントは `"success": false`、`"messageId": null`、および `"error"` フィールドを含む HTTP `200 OK` を返し、同時に `emailDelivery` を記録して `smart_batch_report_delivery_failed` を発火します。

#### エラーコード

| ステータス | エラーコード / 種別 | 原因 |
| --- | --- | --- |
| `401` | `Unauthorized` | JWT が欠落または無効です。 |
| `403` | `Forbidden` | 共有 x402 による実行が試行されました。クライアント別 JWT を使用してください。 |
| `404` | `not_found` | レポート ID が存在しないか、別のクライアントに属しています。 |
| `404` | `template_not_found` | リンクされたテンプレートが見つかりませんでした。 |
| `409` | `MissingParameter` | Joi 検証に失敗しました（例: `recipients` の欠落または無効な値）。 |
| `409` | `send_all_limit` | `50` 行を超えるバッチ（`MAX_SEND_ALL_ROWS`）に対して `sendAll: true` が要求されました。 |
| `409` | `no_pdf_attachments` | リクエストに対して PDF 添付ファイルを解決またはレンダリングできませんでした。 |
| `409` | `row_not_found` | 要求された `rowIndex` がバッチ内に存在しません。 |
| `422` | `UnprocessableEntity` | Mongoose 検証エラーです。 |
| `500` | `invalid_pdf` | 指定された `pdfBase64` または `pdfFiles` ペイロードが有効な PDF ではありません。 |

### Webhook と MCP 統合

- **Webhook**: 配信が成功すると `smart_batch_report_sent`、失敗すると `smart_batch_report_delivery_failed` を自動的に発火し、`SmartReport` に `emailDelivery` を記録します。詳細は [SmartReports Webhook](/verifik-ja/resources/smart-reports-webhooks) を参照してください。
- **MCP 相当ツール**: AI エージェントは `smart_report_send_email` MCP ツール経由でレポートメールを送信できます。詳細は [MCP と AI エージェント](/verifik-ja/smart-reports/mcp-and-ai-agents) を参照してください。

### 注記

- メールトランスポートエラーは非 200 ステータスコードではなく、`messageId: null` と `error` を伴う `success: false` として返されるため、常に `200 OK` ボディ内の `success` を確認してください。
- 1 回の呼び出しで検証ステップの実行、PDF 生成、およびメール送信を行いたい場合は、[Smart Report を実行する](/verifik-ja/smart-reports/run-a-smart-report) を使用してください。
