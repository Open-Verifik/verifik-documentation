`SmartBatch` の単一行（`rowIndex`）上で指定された `sequences` のみをクリアして再キュー登録し、それ以外のすべてのステップの保存済み出力および他のすべての行はそのまま保持します。`rowIndex` と `sequences` はどちらも必須です。

バッチ、対象行、配下の `FeatureRunner` 実行、または実行アイテムが現在処理中の場合、サーバーは `409 Conflict`（`batch_is_processing`、`row_is_processing`、`run_is_processing`、`item_is_processing`）でリクエストを拒否します。

### エンドポイント

```text
POST https://api.verifik.co/v2/smart-batches/{id}/retry-steps
```

このエンドポイントは、クライアント単位の `Authorization: Bearer <VERIFIK_JWT>` を使用することで Smart-Agent プロキシ（`https://ai.verifik.co/v2/smart-batches/{id}/retry-steps`）経由でもアクセスできます。共有 x402 実行は `403 Forbidden` でブロックされます。

### ヘッダー

| 名前 | 値 | 説明 |
| --------------- | ---------------------- | ---------------------------------------- |
| `Content-Type` | `application/json` | リクエストペイロード形式。 |
| `Authorization` | `Bearer <VERIFIK_JWT>` | クライアントスコープの JWT（`authUser.clientId`）。 |

### パラメータ

| 名前 | 型 | 必須 | 説明 |
| ---- | ------ | ---- | ----------- |
| `id` | string | はい | `SmartBatch` の ObjectId。 |

### リクエストボディ

| 名前 | 型 | 必須 | 説明 |
| ----------- | --------- | ---- | ----------- |
| `rowIndex` | integer | はい | 部分的に再試行する行の `0` 始まりインデックス（`>= 0`）。 |
| `sequences` | integer[] | はい | 該当行上でクリアして再実行するステップ順序番号（`>= 0`、最小 `1` 件、最大 `200` 件）。 |

不明なボディキーまたは必須フィールドの不足は Joi バリデーションにより `409 MissingParameter` で拒否されます。

### 補足

- 保存済みの `results` と `errors` は `rowIndex` 上で指定された `sequences` のみがクリアされ、他のすべてのステップ順序の結果はそのまま保持されます。
- 発生しうる `409 Conflict` の理由は `batch_is_processing`、`row_is_processing`、`run_is_processing`、および `item_is_processing` です。
- 無効または空のステップ順序参照を渡すと `400 BadRequest`（`retry_steps_invalid`）が返されます。
- バッチ全体の失敗行や一部成功行を丸ごと再試行するには、[失敗した Smart Batch 行を再試行する](/verifik-ja/smart-reports/retry-failed-batch-rows)を使用してください。
