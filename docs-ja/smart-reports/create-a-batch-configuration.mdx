認証済みクライアントアカウント上にカスタムの `BatchConfiguration` を作成します。対象の `country`、カタログ `AppFeature` ID を参照する順序付きの検証 `steps`、任意の入出力形式、リトライパラメータ、`visitaFlow` ビジュアルグラフ、および完了通知を定義します。

設定を作成しても照会は実行されず、クレジットも消費されません。なお、このエンドポイントは HTTP `201` ではなく `200` を返し、`data` に保存済みの設定を含めます。スキーマ検証は Mongoose によって直接処理されるため、無効または不足しているフィールドがある場合は `422 UnprocessableEntity` を返します。

### エンドポイント

```
POST https://api.verifik.co/v2/batch-configurations
```

クライアント単位の `Authorization: Bearer <VERIFIK_JWT>` ヘッダーを使用することで、Smart-Agent プロキシ（`https://ai.verifik.co/v2/batch-configurations`）経由でもアクセスできます。共有 x402 実行は `403 Forbidden` でブロックされます。

### ヘッダー

| 名前 | 値 |
| ---- | ----- |
| Content-Type | `application/json` |
| Authorization | `Bearer <VERIFIK_JWT>` |

トークンは **クライアント JWT** である必要があります。認証情報がないか無効な場合は `401 Unauthorized` を返します。

### リクエストボディ

| 名前 | 型 | 必須 | 説明 |
| ---- | ---- | ---- | ----------- |
| `name` | string | はい | 設定の表示名。トリム済み、最大 `150` 文字。 |
| `country` | string | はい | 設定の対象国スコープ。サーバー側でトリムおよび大文字化されます（例: `CO`）。 |
| `steps` | object[] | はい | 検証ステップオブジェクトの順序付き配列（下記の `steps[]` フィールドを参照）。 |
| `description` | string | いいえ | ワークフローの任意の概要。最大 `800` 文字。 |
| `executor` | string | いいえ | 実行ターゲット: `queue`、`featureRunner`、または `browser`。既定値は `featureRunner` です（`browser` として永続化されますが、ヘッドレスランナーは `FeatureRunner` 経由で実行します）。 |
| `inputFormat` | string | いいえ | 既定の入力形式: `csv`、`jsonl`、または `xlsx`。既定値は `csv`。 |
| `outputFormat` | string | いいえ | 既定の出力形式: `csv`、`jsonl`、または `xlsx`。既定値は `csv`。 |
| `mergeStrategy` | string | いいえ | ステップ実行戦略: `sequential`、`parallel-independent`、または `parallel-with-fallback`。既定値は `sequential`。 |
| `notification` | object | いいえ | 完了通知設定（`webhookUrl` および `emailOnCompletion`）。下記の `notification` フィールドを参照。 |
| `scheduleExpression` | string | いいえ | 自動実行用の任意のスケジュール式。 |
| `preferredReportTemplate` | string | いいえ | この設定配下のバッチの既定レポートテンプレートとしてリンクされる `SmartReportTemplate` ObjectId。 |
| `visitaFlow` | object | いいえ | ステップ連鎖を定義するビジュアルノードグラフ。`{{results.N.field}}` プレースホルダーは、導出された入力スキーマの手動入力から除外されます。 |
| `isActive` | boolean | いいえ | 設定が有効かどうか。既定値は `true`。 |

#### `steps[]` オブジェクトのフィールド

| 名前 | 型 | 必須 | 説明 |
| ---- | ---- | ---- | ----------- |
| `appFeature` | string | はい | このステップで実行する `AppFeature` の ObjectId。 |
| `sequence` | number | はい | 1 始まりのステップ実行順序（`>= 1`）。 |
| `enabled` | boolean | いいえ | バッチ実行時にこのステップを実行するかどうか。既定値は `true`。 |
| `parameterDefaults` | object | いいえ | このステップに固定された静的パラメータ値または `{{results.N.field}}` 式。既定値は `{}`。 |
| `queryMode` | string | いいえ | 機能が複数の照会モードをサポートしている場合の任意の依存グループセレクタ。 |
| `inputFieldMapping` | object | いいえ | 入力列名を API パラメータ名にマッピングします（`inputColumn -> apiParam`）。既定値は `{}`。 |
| `outputFieldsToKeep` | string[] | いいえ | 表形式の結果に保持する出力フィールドのサブセット。既定値は `[]`。 |
| `maxRetries` | number | いいえ | 一時的なステップ失敗時の最大リトライ回数（`>= 0`）。既定値は `3`。 |
| `retryDelayBaseSeconds` | number | いいえ | 秒単位の基本バックオフ遅延（`>= 1`）。既定値は `4`。 |
| `timeoutSeconds` | number | いいえ | 秒単位のステップ実行タイムアウト（`>= 5`）。既定値は `30`。 |

#### `notification` オブジェクトのフィールド

| 名前 | 型 | 必須 | 説明 |
| ---- | ---- | ---- | ----------- |
| `webhookUrl` | string | いいえ | バッチ完了時に通知する HTTPS エンドポイント。`webhookUrl` を指定すると、クライアント用の有効な Verifik Webhook が自動的に同期されます。 |
| `emailOnCompletion` | string[] | いいえ | バッチ完了時に通知を受け取る受信者メールアドレスの一覧。 |

### 補足

- 成功時は（`201` ではなく）HTTP **`200`** を返し、`data` に作成されたドキュメントが含まれます。
- このエンドポイントには Joi ミドルウェアがありません。Mongoose のスキーマ検証が必須フィールドや数値制約を強制し、失敗時には `422 UnprocessableEntity` を返します。
- `executor` が `"featureRunner"`（既定値）の場合、サーバーは設定ドキュメントに `"browser"` として永続化しつつ、ヘッドレスランナーは引き続き `FeatureRunner` 経由で実行します。
- `notification.webhookUrl` を設定すると、クライアント用の有効な Verifik Webhook が自動的に作成または同期されます。
- 続いて、[バッチ設定の入力スキーマを取得する](/verifik-ja/smart-reports/retrieve-configuration-input-schema)を呼び出し、レポートを実行する前に導出されたフィールドと `exampleInput` を確認してください。
