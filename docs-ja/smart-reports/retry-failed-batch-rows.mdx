すでに完了した行に影響を与えることなく、`SmartBatch` 上の `"failed"` または `"partial"` ステータスの行を再キュー登録します。任意の `rowIndexes` を渡すと特定のサブセットの行のみを再試行でき、`rowIndexes` を省略するとバッチ内のすべての `"failed"` および `"partial"` 行が再試行されます。

バッチが現在 `"processing"` ステータスの場合、リクエストは `409 Conflict`（`batch_is_processing`）で失敗します。`retried: 0` が返された場合、対象となる failed または partial 行が一致しなかったことを示します。

### エンドポイント

```text
POST https://api.verifik.co/v2/smart-batches/{id}/retry-failed
```

このエンドポイントは、クライアント単位の `Authorization: Bearer <VERIFIK_JWT>` を使用することで Smart-Agent プロキシ（`https://ai.verifik.co/v2/smart-batches/{id}/retry-failed`）経由でもアクセスできます。共有 x402 実行は `403 Forbidden` でブロックされます。

### ヘッダー

| 名前 | 値 | 説明 |
| --------------- | ---------------------- | ---------------------------------------- |
| `Content-Type` | `application/json` | リクエストペイロード形式。 |
| `Authorization` | `Bearer <VERIFIK_JWT>` | クライアントスコープの JWT（`authUser.clientId`）。 |

### パラメータ

| 名前 | 型 | 必須 | 説明 |
| ---- | ------ | ---- | ----------- |
| `id` | string | はい | `SmartBatch` の ObjectId。 |

### リクエストボディ

| 名前 | 型 | 必須 | 説明 |
| ------------ | --------- | ---- | ----------- |
| `rowIndexes` | integer[] | いいえ | 再試行する特定の `0` 始まり行インデックス（`>= 0`、最大 `10000` 件）。省略するとすべての `"failed"` および `"partial"` 行を再試行します。 |

不明なボディキーは Joi バリデーションにより `409 MissingParameter` で拒否されます。

### 補足

- すべての `"failed"` および `"partial"` 行を一括で再試行するには `{}` を送信（または `rowIndexes` を省略）してください。
- `rowIndexes` を指定した場合、そのインデックスが含まれていても `"completed"` または `"pending"` ステータスの行は無視されます。
- 他のステップの結果を保持したまま単一行内の特定のステップ順序のみを再実行するには、[Smart Batch 行のステップを再試行する](/verifik-ja/smart-reports/retry-batch-row-steps)を使用してください。
