Guía de API Headless

Puedes automatizar SmartReports al 100% desde tu backend, cola de workers o pipeline de CI sin abrir jamás la interfaz web de Smart-Agent. Cada operación está expuesta por HTTPS tanto en https://api.verifik.co como en https://ai.verifik.co usando exactamente las mismas rutas /v2/....

Se requiere Bearer JWT por cliente

Cada solicitud de esta guía exige el token de tu propia cuenta de Verifik:

Authorization: Bearer <VERIFIK_JWT>

Nunca expongas VERIFIK_JWT en el navegador ni en código del lado del cliente. Las solicitudes enviadas sin un Bearer JWT por cliente a través de https://ai.verifik.co son rechazadas por smartReportAuthGuard con 403 Forbidden.

Cómo elegir un flujo de trabajo​

Flujo de trabajoEndpoint de entradaLímite de filasIdeal para
1. Ejecución directa de preset (Sync)POST /v2/smart-reports/run (mode: "sync")1–5 filasVerificación inmediata + PDF + Puntaje de Verificación en una sola solicitud HTTP (límite de 90s con cambio automático a async).
2. Ejecución asíncrona + Webhooks / PollingPOST /v2/smart-reports/run (mode: "async")1–500 filasLotes de varios sujetos (> 5 filas) o fuentes gubernamentales lentas impulsadas por webhooks smart_batch_* o sondeo (polling).
3. Receta reutilizable personalizadaPOST /v2/smart-batch-presets/{systemKey}/clone o POST /v2/batch-configurations + /v2/smart-batchesHasta 20,000 filas (SMART_BATCH_MAX_ROWS)Marca y diseño propios, secciones generadas con IA, carga de archivos CSV/XLSX/JSONL y generación de reportes por fila.

Flujo 1: Ejecución directa de preset (ruta más rápida)​

La forma más rápida de integrar SmartReports es ejecutar un preset integrado de Verifik por su systemKey. POST /v2/smart-reports/run clona o reutiliza automáticamente la configuración del preset en tu cliente, valida las entradas requeridas, ejecuta los pasos de verificación encadenados en el servidor, calcula el verificationScore, renderiza el PDF, opcionalmente envía correos a los destinatarios y dispara webhooks.

Paso 1: Descubrir presets y entradas requeridas​

Consulta GET /v2/smart-batch-presets (sin costo de créditos) para inspeccionar los presets disponibles, cantidad de pasos, disponibilidad y el inputSchema derivado:

GET https://api.verifik.co/v2/smart-batch-presets?country=CO&category=citizen
Authorization: Bearer <VERIFIK_JWT>

Campos clave devueltos por cada preset:

  • systemKey: Identificador estable para pasar a POST /v2/smart-reports/run (por ejemplo "co.citizen.comprehensive").
  • available y unavailableFeatureCodes: Confirma que todos los endpoints del preset están disponibles en el entorno.
  • inputSchema:
    • stepCount y estimatedCreditsPerRow: Total de pasos de verificación y consumo estimado de créditos por fila de entrada.
    • requiredFields y optionalFields: Nombres exactos de campos, tipos, enumeraciones, valores predeterminados y condiciones requiredWhen.
    • jsonSchema y exampleInput: JSON Schema listo para usar y objeto de entrada de ejemplo.

Paso 2: Ejecutar de forma síncrona (mode: "sync")​

Envía POST /v2/smart-reports/run con systemKey, inputs y mode: "sync" (valor predeterminado al enviar 1–5 filas):

{
  "systemKey": "co.citizen.comprehensive",
  "inputs": {
    "documentType": "CC",
    "documentNumber": "123456789"
  },
  "mode": "sync",
  "generatePdf": true,
  "includePdfBase64": false,
  "score": true,
  "emailTo": ["compliance@yourcompany.com"],
  "emailLanguage": "en",
  "externalRefId": "applicant-9841"
}

Ejecución síncrona y cambio automático a 202​

  • Tope de filas: La ejecución síncrona acepta como máximo 5 filas (MAX_SYNC_ROWS = 5). Enviar más de 5 filas con mode: "sync" devuelve 409 Conflict (sync_row_limit_exceeded).
  • Límite de ejecución de 90s: La ejecución síncrona espera hasta 90 segundos (SYNC_DEADLINE_MS = 90000) a que respondan los registros externos. Si alguna fuente externa sigue ejecutándose al cumplirse los 90s, Verifik marca el reporte para finalización en segundo plano (asyncFinalize: true) y devuelve sin interrupciones HTTP 202 Accepted (mode: "async") con pollUrl, downloadUrl y htmlUrl—tu ejecución y el progreso ya consumido nunca se pierden.
  • Incluir bytes PDF en línea: Establece "includePdfBase64": true para incluir data.pdf.buffer (bytes del PDF en base64) directamente en la respuesta JSON 200 OK. Déjalo en false (predeterminado) para mantener cargas ligeras y descargar el binario PDF desde downloadUrl.

Flujo 2: Ejecución headless asíncrona + Webhooks + Polling​

Usa mode: "async" siempre que envíes más de 5 filas (hasta 500 filas por llamada a POST /v2/smart-reports/run), o cuando prefieras encolamiento inmediato con 202 Accepted incluso para 1–5 filas.

Paso 1: Encolar con mode: "async"​

Pasa mode: "async", una sobrescritura opcional de webhookUrl por ejecución, externalRefId para correlación y opcionalmente emailTo:

{
  "systemKey": "co.citizen.comprehensive",
  "inputs": [
    { "documentType": "CC", "documentNumber": "123456789" },
    { "documentType": "CC", "documentNumber": "987654321" }
  ],
  "mode": "async",
  "webhookUrl": "https://api.yourcompany.com/webhooks/verifik-reports",
  "externalRefId": "onboarding-batch-42",
  "emailTo": ["ops@yourcompany.com"],
  "emailLanguage": "en"
}

Verifik responde de inmediato HTTP 202 Accepted:

{
  "data": {
    "mode": "async",
    "report": {
      "_id": "6740a1b2c3d4e5f678909999",
      "status": "generating",
      "smartBatch": "6740a1b2c3d4e5f678908888",
      "externalRefId": "onboarding-batch-42",
      "webhookUrl": "https://api.yourcompany.com/webhooks/verifik-reports"
    },
    "batch": {
      "_id": "6740a1b2c3d4e5f678908888",
      "status": "processing",
      "totalRows": 2,
      "completedRows": 0,
      "failedRows": 0,
      "partialRows": 0
    },
    "pollUrl": "/v2/smart-reports/6740a1b2c3d4e5f678909999",
    "downloadUrl": "/v2/smart-reports/6740a1b2c3d4e5f678909999/download",
    "htmlUrl": "/v2/smart-reports/6740a1b2c3d4e5f678909999/html"
  }
}

Paso 2: Recibir webhooks o consultar estado (polling)​

Una vez que FeatureRunner completa el lote en segundo plano, Verifik renderiza automáticamente el PDF, calcula verificationScore, envía emailTo (si se proporcionó) y entrega eventos webhook tipados:

  • Impulsado por webhooks (recomendado): Escucha smart_batch_report_generated (PDF listo), smart_batch_report_generation_failed, smart_batch_report_sent y smart_batch_report_delivery_failed en tu webhookUrl (o batchConfiguration.notification.webhookUrl). Consulta Webhooks de SmartReports para ver los payloads exactos y reglas de reintento.
  • Alternativa por polling: Consulta GET /v2/smart-reports/{id} (el pollUrl devuelto en 202) hasta que data.status deje de ser "generating" ("generated", "sent" o "failed").

Paso 3: Descargar PDF o recuperar HTML + puntaje​

  • Descarga binaria de PDF:
GET https://api.verifik.co/v2/smart-reports/{id}/download
Authorization: Bearer <VERIFIK_JWT>

Devuelve application/pdf con Content-Disposition: attachment; filename="Consulta_1.pdf". Pasa ?rowIndex=1 para renderizar y descargar una fila específica de un lote multifila.

  • JSON estructurado de HTML + Puntaje de Verificación (sin iniciar Chromium PDF):
GET https://api.verifik.co/v2/smart-reports/{id}/html?rowIndex=0&preview=false&score=true
Authorization: Bearer <VERIFIK_JWT>

Devuelve { data: { reportId, batchId, templateId, rowIndex, html, verificationScore, row } }.

Flujo 3: Receta reutilizable personalizada​

Cuando requieras marca propia, diseños de sección personalizados, cadenas de pasos editadas o ingesta de hojas de cálculo por encima de 500 filas, gestiona explícitamente los recursos de configuración, plantilla y lote.

Paso 1: Clonar un preset o crear una configuración​

  • Clonar un preset (idempotente):
POST https://api.verifik.co/v2/smart-batch-presets/{systemKey}/clone
Authorization: Bearer <VERIFIK_JWT>

Devuelve { data: { batchConfiguration, template, reused } }. Si tu cliente ya cuenta con un clon activo para ese systemKey (sin pasos adicionales agregados por el cliente más allá del preset), Verifik lo reutiliza y alinea (reused: true) en lugar de duplicar configuraciones.

  • O crear una configuración personalizada:
POST https://api.verifik.co/v2/batch-configurations
Authorization: Bearer <VERIFIK_JWT>
Content-Type: application/json

Especifica name, country, steps[] (ordenados con sequence, appFeature, opcional parameterDefaults, queryMode, inputFieldMapping), mergeStrategy, preferredReportTemplate y notification (webhookUrl, emailOnCompletion).

Paso 2: Inspeccionar el esquema exacto de entrada​

Antes de armar encabezados CSV o enviar filas, consulta:

GET https://api.verifik.co/v2/batch-configurations/{id}/input-schema
Authorization: Bearer <VERIFIK_JWT>

Esto devuelve los campos exactos requiredFields, optionalFields, estimatedCreditsPerRow, jsonSchema y exampleInput resueltos entre todos los pasos habilitados (excluyendo campos ya suministrados vía parameterDefaults o encadenamientos {{results.N.*}}).

Paso 3: Previsualizar y personalizar la plantilla de reporte​

Las plantillas propiedad del cliente (type: "client") pueden inspeccionarse, generarse, previsualizarse sin costo de créditos y actualizarse vía API:

  1. Descubrir rutas de datos disponibles: POST /v2/smart-report-templates/introspect con { "sampleData": { ... } } devuelve la paleta de campos planos/anidados (dot paths) para vincular en la plantilla.
  2. Generar o editar secciones de diseño con IA: POST /v2/smart-report-templates/generate-layout con { "prompt": "...", "previewData": { ... }, "mode": "create" | "edit" | "append" } genera sections[] (o modifica una única selectedSection).
  3. Renderizar vista previa HTML rápida en vivo: POST /v2/smart-report-templates/preview-html renderiza en memoria una plantilla sin guardar + sampleData sin abrir Chromium ni persistir en MongoDB, devolviendo { data: { html, verificationScore } }.
  4. Guardar actualizaciones: PUT /v2/smart-report-templates/{id} guarda sections, reportTheme, logo, watermark, signature, security (contraseña de PDF) o pdfEngine en tu plantilla de cliente.
Las plantillas integradas del sistema son de solo lectura

Intentar PUT o DELETE sobre una plantilla "System" integrada falla con 403 Forbidden (system_template_readonly). Clona primero un preset (POST /v2/smart-batch-presets/{systemKey}/clone) o crea una nueva plantilla (POST /v2/smart-report-templates).

Paso 4: Crear y ejecutar lotes grandes (hasta 20,000 filas)​

Para lotes grandes que superan el límite de 500 filas de /v2/smart-reports/run:

  • Desde filas JSON: POST /v2/smart-batches con { "batchConfiguration": "<CONFIG_ID>", "name": "Monthly Onboarding", "rows": [ ... ] }, y luego inicia la ejecución con POST /v2/smart-batches/{id}/start.
  • Desde archivos CSV / XLSX / JSONL: POST /v2/smart-batches/from-file analiza texto sin formato o URLs de datos base64 en el servidor y valida cada fila frente a las dependencias de pasos antes de gastar créditos (límite predeterminado SMART_BATCH_MAX_ROWS = 20000 filas):
{
  "batchConfiguration": "6740a1b2c3d4e5f678901111",
  "name": "Q4 Driver Screening",
  "format": "csv",
  "autoStart": true,
  "content": "documentType,documentNumber\nCC,123456789\nCC,987654321"
}

Paso 5: Generar, enviar por correo y descargar reportes por fila​

Una vez que el lote finalice (GET /v2/smart-batches/{id}/progress o webhook smart_batch_batch_completed):

  1. Inspecciona el modelo de datos de reporte compuesto de una fila: GET /v2/smart-batches/{id}/rows/{rowIndex}/report.
  2. Crea un registro SmartReport vinculado a tu plantilla y lote: POST /v2/smart-reports con { "template": "<TEMPLATE_ID>", "smartBatch": "<BATCH_ID>", "rowIndex": 0, "externalRefId": "row-0", "webhookUrl": "https://..." }.
  3. Renderiza el PDF y el Puntaje de Verificación: POST /v2/smart-reports/{id}/generate (admite rowIndex, engine, score, scoreProfile).
  4. Envía por correo una fila o hasta 50 filas como adjuntos PDF separados: POST /v2/smart-reports/{id}/send-email ({ "recipients": ["client@example.com"], "language": "es", "rowIndex": 0 } o "sendAll": true).
  5. Descarga el PDF: GET /v2/smart-reports/{id}/download (con ?rowIndex=0 opcional).

Los ejemplos siguientes listan presets, ejecutan POST /v2/smart-reports/run, manejan tanto respuestas síncronas 200 como asíncronas 202 (sondeando GET /v2/smart-reports/{id} hasta completarse), inspeccionan verificationScore y descargan el PDF finalizado.

import fs from 'node:fs/promises';

const BASE_URL = 'https://api.verifik.co';
const JWT = process.env.VERIFIK_JWT;

if (!JWT) {
  throw new Error('Define VERIFIK_JWT en tu entorno de servidor');
}

const headers = {
  Authorization: `Bearer ${JWT}`,
  'Content-Type': 'application/json',
  Accept: 'application/json',
};

async function apiFetch(path, options = {}) {
  const res = await fetch(`${BASE_URL}${path}`, {
    ...options,
    headers: { ...headers, ...(options.headers || {}) },
  });
  const payload = await res.json();
  if (!res.ok) {
    throw new Error(`HTTP ${res.status} (${payload.code}): ${payload.message}`);
  }
  return { status: res.status, data: payload.data };
}

async function runHeadlessReport() {
  // 1. Descubrir presets y esquema de entrada requerido
  const { data: presets } = await apiFetch('/v2/smart-batch-presets?country=CO&category=citizen');
  const preset = presets.find((p) => p.systemKey === 'co.citizen.comprehensive' && p.available);
  if (!preset) throw new Error('El preset co.citizen.comprehensive no está disponible');

  console.log('Créditos estimados/fila:', preset.inputSchema.estimatedCreditsPerRow);
  console.log('Campos requeridos:', preset.inputSchema.requiredFields.map((f) => f.field));

  // 2. Ejecutar verificación + puntaje + generación de PDF en una sola llamada
  const runRes = await apiFetch('/v2/smart-reports/run', {
    method: 'POST',
    body: JSON.stringify({
      systemKey: preset.systemKey,
      inputs: {
        documentType: 'CC',
        documentNumber: '123456789',
      },
      mode: 'sync',
      generatePdf: true,
      score: true,
      externalRefId: 'case-12345',
      // Sobrescritura opcional de webhook por ejecución:
      // webhookUrl: 'https://api.yourcompany.com/webhooks/verifik-reports',
    }),
  });

  let report = runRes.data.report;
  const reportId = report._id;

  // 3. Si es 202 async (o cambio automático tras >90s), consultar GET /v2/smart-reports/{id}
  if (runRes.status === 202 || runRes.data.mode === 'async') {
    console.log('Reporte encolado en async, sondeando:', runRes.data.pollUrl);
    for (let attempt = 0; attempt < 30; attempt += 1) {
      await new Promise((resolve) => setTimeout(resolve, 4000));
      const polled = await apiFetch(`/v2/smart-reports/${reportId}`);
      report = polled.data;
      if (['generated', 'sent', 'failed'].includes(report.status)) break;
    }
    if (report.status === 'failed') {
      throw new Error(`Falló el reporte: ${report.error?.message}`);
    }
  }

  console.log('Report ID:', reportId);
  console.log('Verification Score:', report.verificationScoreSummary);

  // 4. Descargar el binario PDF renderizado
  const pdfRes = await fetch(`${BASE_URL}/v2/smart-reports/${reportId}/download`, {
    headers: { Authorization: `Bearer ${JWT}` },
  });
  if (!pdfRes.ok) throw new Error(`Falló la descarga: HTTP ${pdfRes.status}`);

  const pdfBuffer = Buffer.from(await pdfRes.arrayBuffer());
  await fs.writeFile(`smart-report-${reportId}.pdf`, pdfBuffer);
  console.log(`Guardado smart-report-${reportId}.pdf (${pdfBuffer.length} bytes)`);
}

runHeadlessReport().catch((err) => {
  console.error(err);
  process.exit(1);
});
import os
import time
import requests

BASE_URL = "https://api.verifik.co"
JWT = os.environ["VERIFIK_JWT"]

HEADERS = {
    "Authorization": f"Bearer {JWT}",
    "Content-Type": "application/json",
    "Accept": "application/json",
}


def run_headless_report() -> None:
    # 1. Descubrir presets y campos requeridos
    presets_resp = requests.get(
        f"{BASE_URL}/v2/smart-batch-presets",
        params={"country": "CO", "category": "citizen"},
        headers=HEADERS,
        timeout=30,
    )
    presets_resp.raise_for_status()
    presets = presets_resp.json()["data"]
    preset = next((p for p in presets if p["systemKey"] == "co.citizen.comprehensive" and p["available"]), None)
    if not preset:
        raise RuntimeError("El preset co.citizen.comprehensive no está disponible")

    print("Créditos estimados/fila:", preset["inputSchema"]["estimatedCreditsPerRow"])

    # 2. Ejecutar reporte en modo headless
    run_resp = requests.post(
        f"{BASE_URL}/v2/smart-reports/run",
        headers=HEADERS,
        json={
            "systemKey": preset["systemKey"],
            "inputs": {
                "documentType": "CC",
                "documentNumber": "123456789",
            },
            "mode": "sync",
            "generatePdf": True,
            "score": True,
            "externalRefId": "case-12345",
        },
        timeout=120,
    )
    if run_resp.status_code >= 400:
        raise RuntimeError(f"Error de ejecución {run_resp.status_code}: {run_resp.text}")

    payload = run_resp.json()["data"]
    report = payload["report"]
    report_id = report["_id"]

    # 3. Hacer polling si devolvió 202 Accepted (modo async o respaldo tras >90s)
    if run_resp.status_code == 202 or payload.get("mode") == "async":
        print("Sondeando reporte async:", payload["pollUrl"])
        for _ in range(30):
            time.sleep(4)
            poll_resp = requests.get(f"{BASE_URL}/v2/smart-reports/{report_id}", headers=HEADERS, timeout=30)
            poll_resp.raise_for_status()
            report = poll_resp.json()["data"]
            if report["status"] in ("generated", "sent", "failed"):
                break
        if report["status"] == "failed":
            raise RuntimeError(f"Falló la generación del reporte: {report.get('error')}")

    print("Report ID:", report_id)
    print("Verification Score Summary:", report.get("verificationScoreSummary"))

    # 4. Descargar el archivo PDF
    pdf_resp = requests.get(
        f"{BASE_URL}/v2/smart-reports/{report_id}/download",
        headers={"Authorization": f"Bearer {JWT}"},
        timeout=60,
    )
    pdf_resp.raise_for_status()
    filename = f"smart-report-{report_id}.pdf"
    with open(filename, "wb") as f:
        f.write(pdf_resp.content)
    print(f"Guardado {filename} ({len(pdf_resp.content)} bytes)")


if __name__ == "__main__":
    run_headless_report()

Guía de manejo de errores​

Los endpoints de SmartReports validan los esquemas de solicitud con Joi antes de ejecutarse y verifican la propiedad del tenant y las invariantes en tiempo de ejecución durante el procesamiento. Los errores siguen la estructura { "message": "...", "code": "..." }.
