데이터 보존

계정, 프로젝트, 프로젝트 플로우 설정이 문서 이미지, 문서 검증과 함께 저장된 추출 필드, 얼굴 이미지를 Verifik가 얼마나 보관하는지 정합니다. 정책은 새 레코드가 만들어질 때 찍힙니다. 이후의 변경은 이미 있는 레코드를 다시 쓰지 않습니다.

이미지가 삭제되어도 청구 기록, 크레딧 차감, 사용 이력은 그대로 남습니다.

모드​

모드효과
store레코드를 보관합니다. retentionHours를 0보다 큰 수로 두면 그 시간이 지난 뒤 삭제 대상이 됩니다. retentionHours를 생략하면 기한 없이 보관합니다.
ephemeral웹훅이 있으면 웹훅 보관 시간이 끝날 때, 웹훅이 없으면 다음 삭제 실행 때 삭제 대상이 됩니다. retentionHours는 무시됩니다.
none문서 이미지와 저장된 추출 필드는 ephemeral과 같은 시점을 사용합니다. 이 모드의 얼굴 이미지는 기록되지 않습니다. SmartEnroll 응답은 호스팅 URL을 빼고 hasFrontImage 또는 hasBackImage를 돌려줍니다.

SmartEnroll 문서 스캔에서 retentionHours가 있는 store 규칙은 그래도 24시간 보관, 웹훅이 있으면 웹훅 보관을 사용합니다. 시간이 없는 store는 그 이미지를 보관합니다.

ephemeral과 none은 삭제 시점이 같습니다. 얼굴 이미지와 SmartEnroll이 호스팅 URL을 돌려주는지에서 달라집니다.

이 정책이 적용하는 유형​

키대상
documentImages문서 검증의 앞면과 뒷면 사진. url과 backUrl 뒤의 호스팅 파일을 포함합니다.
ocrExtraction그 검증에 저장된 추출 결과.
faceImages등록 또는 로그인에 저장된 셀피 및 문서 얼굴 이미지.

각 키에 mode를 설정하세요. 최상위 mode가 none이면 비워 둔 키에 복사됩니다. 최상위 store 또는 ephemeral은 그 키를 바꾸지 않습니다. 필요한 키마다 값을 넣는 요청이 확실합니다.

이 정책 밖에 남는 것​

다음 기록은 자체 저장 규칙을 따릅니다. 보존 모드를 저장해도 이들은 삭제되지 않습니다.

  • 문서 라이브니스 사진
  • 라이브니스 점수와 세션 결과
  • 웹훅 본문. 페이로드에 실린 추출 결과를 포함합니다
  • API 응답 로그
  • Smart Access가 다시 온 사람을 맞출 때 쓰는 생체 템플릿과 얼굴 컬렉션
  • Human Auth 암호화 자격 증명, 영지식 산출물, 라이브니스 영상
  • Human Auth 자격 증명을 두는 저장 위치
  • 보존 스탬프가 생기기 전에 만들어진 문서 검증과 신원 이미지

호스팅된 문서 이미지는 일반 URL을 사용합니다. URL은 그 파일이 삭제될 때까지 유효합니다. 모든 이미지 URL을 민감한 값으로 다루세요.

우선순위​

유효 정책은 이 순서로 정해집니다.

  1. 계정. 클라이언트 설정에 저장된 정책.
  2. 프로젝트. 프로젝트의 dataRetention이 계정에서 그 객체가 지정한 필드를 바꿉니다.
  3. 프로젝트 플로우. 플로우의 dataRetention이 프로젝트에서 그 객체가 지정한 필드를 바꿉니다.

한 단계가 필드를 생략하면 더 넓은 값이 남습니다. 아무것도 설정하지 않으면 적용되는 모든 유형은 기한 없는 store이고, 웹훅 보관은 24시간입니다.

저장한 정책이 각 실행 인스턴스에 반영되기까지 약 1분이 걸릴 수 있습니다.

웹훅 보관​

webhookHoldHours는 24에서 72 사이의 정수입니다. 기본값은 24입니다.

웹훅이 있으면 none과 ephemeral 레코드는 전달이 끝날 수 있도록 적어도 이 시간 동안 남습니다. 그 등록에 대한 웹훅이 전달된 뒤, 이 모드의 이미지는 이후 삭제 실행에서 제거될 수 있습니다. 페이로드의 이미지 URL은 그 전달 이후 동작하지 않을 수 있습니다. 웹훅을 처리하는 동안 아직 필요한 이미지를 복사하세요.

SmartEnroll 종료 이벤트는 onboarding_app_registration_completed, onboarding_app_registration_needs_manual_verification, onboarding_app_registration_completed_without_kyc, onboarding_app_registration_failed입니다.

보존 정책은 웹훅 본문을 가리지 않습니다. 페이로드에는 전체 추출 결과가 들어갈 수 있습니다.

삭제가 지우고, 가리고, 남기는 것​

문서 검증이 삭제될 때:

동작필드
제거호스팅 이미지 파일. url, backUrl, 파일 목록이 비워집니다.
마스킹저장된 추출 결과와 fullName.
평문 유지documentNumber, 이름, 성, 요청 매개변수, 검증에 저장된 스크리닝 결과.
행은 유지상태, 유형, createdAt. 이 행을 읽는 사용량 집계는 계속 포함합니다.

얼굴 이미지 삭제는 저장된 이미지 바이트를 지웁니다.

추출 전체의 암호화된 사본은 스캔 후 30일이 지나면 제거됩니다. 눈에 보이는 저장 필드가 이미 마스킹된 경우에도 같습니다.

크레딧 차감은 스캔이 성공하면 기록됩니다. 삭제는 청구 기록과 사용 이력을 남겨 두고, 차감을 되돌리지 않습니다.

문서 검증이나 앱 등록을 삭제하면 저장된 이미지 파일과 검증 행이 함께 사라집니다. 그 행으로 만든 사용 이력은 그 삭제만큼 줄어듭니다. 삭제 작업은 행을 남겨 둡니다.

삭제가 실행되는 시점​

레코드는 retention.purgeAfter에 삭제 대상이 됩니다. 예약된 삭제는 약 15분마다 대상 레코드를 제거합니다. 실제 삭제는 다음 성공 실행에서 일어나므로, 파일은 purgeAfter 이후 잠시 남을 수 있습니다. 한 번 실행은 제한된 묶음만 처리합니다. 대기열이 크면 여러 번 실행이 필요합니다.

수동 삭제 엔드포인트는 없습니다. 정책 객체의 allowManualDelete는 정책과 함께 저장될 뿐, 별도의 삭제 호출을 열지 않습니다.

정책은 새 레코드에 적용됩니다​

스탬프는 레코드가 만들어질 때 기록됩니다. 계정에 이미 있는 레코드는 자기 스탬프를 유지합니다. 스탬프가 없는 레코드는 그대로 남습니다. 계정을 none으로 바꿔도 그 변경 전에 저장된 이력은 남습니다.

프로젝트가 없는 스캔​

POST /v2/ocr/scan-prompt와 POST /v2/ocr/scan-agent는 호출이 프로젝트에 묶여 있지 않을 때 이 규칙을 따릅니다.

  • 이미지는 호스팅 저장소에 올라가지 않습니다.
  • 응답의 url과 backUrl은 보낸 이미지의 data: URI입니다. 그 응답에 속합니다. 추출 결과를 저장하고, 사진이 더 필요하면 이미지 사본을 직접 보관하세요.
  • 응답 본문에는 전체 추출 결과가 있습니다.
  • 저장되는 검증 행은 마스킹된 추출 결과와 마스킹된 fullName을 둡니다. 그 행의 documentNumber는 평문으로 남습니다.
  • 추출 전체의 암호화된 사본은 30일 뒤에 제거됩니다.

SmartEnroll 문서 스캔은 앱 등록에 묶이며, 계정·프로젝트·플로우로 결정된 정책을 사용합니다. 응답에는 마스킹되지 않은 추출 결과가 있습니다. ocrExtraction이 none이면 저장된 행은 마스킹됩니다. none과 ephemeral에서는 응답이 호스팅 URL을 생략합니다.

Smart Access​

Smart Access 로그인 플로우(login 프로젝트 플로우)는 로그인 셀피에 보존을 찍습니다.

  • faceImages가 none이면 로그인 셀피는 저장되지 않습니다.
  • ephemeral은 다음 삭제 실행까지 셀피를 저장합니다. 로그인 플로우는 웹훅 보관 없이 찍힙니다.
  • store는 셀피를 보관합니다. retentionHours가 있으면 그 시간 동안입니다.

다시 온 사람을 맞출 때는 생체 템플릿과 얼굴 컬렉션을 사용합니다. 이 정책을 바꿔도 그 템플릿은 남습니다. 로그인 라이브니스 결과와 로그인 웹훅 본문도 남습니다.

Human Auth​

Human Auth 온보딩 중에 만들어진 문서 검증은 위의 SmartEnroll 규칙을 사용합니다.

Human Auth 프로젝트는 faceImages를 none으로 고정할 수 있습니다. 그 모드에서는 셀피가 저장되지 않고, 저장된 셀피를 읽는 문서-셀피 비교는 실행되지 않습니다.

라이브니스 영상, 영지식 산출물, 저장 단계가 만드는 암호화 자격 증명은 자체 규칙을 따릅니다. 그 자격 증명의 저장 위치를 고르는 일은 이 정책과 별개입니다.

dataRetention 객체​

PUT /v3/projects/{id}에 이 객체를 보냅니다. null을 보내면 계정 정책을 다시 상속합니다.

프로젝트 플로우에 같은 형태가 있으면, 그 플로우에서 만들어진 레코드에 대해 프로젝트를 대체합니다.

{
  "dataRetention": {
    "mode": "none",
    "webhookHoldHours": 24,
    "types": {
      "documentImages": { "mode": "none" },
      "ocrExtraction": { "mode": "none" },
      "faceImages": { "mode": "store", "retentionHours": 72 }
    }
  }
}
필드타입설명
modestore, ephemeral, none계정 또는 재정의의 기준. 각 유형도 설정하세요.
webhookHoldHours정수, 24–72웹훅이 있을 때의 최소 보관. 기본값 24.
types.documentImages.mode모드문서 사진.
types.documentImages.retentionHours숫자 또는 생략그 유형이 store이고 숫자가 0보다 클 때 사용. SmartEnroll 문서 이미지에서는 무시됩니다.
types.ocrExtraction같은 형태저장된 추출 결과.
types.faceImages같은 형태셀피와 문서 얼굴 이미지. none이면 셀피는 기록되지 않습니다.

저장된 정책에 다른 유형 키가 있을 수 있습니다. 삭제는 그 키를 적용하지 않습니다.
