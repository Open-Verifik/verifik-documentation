Crie uma `BatchConfiguration` personalizada na sua conta de cliente autenticada. Defina o `country` de destino, as `steps` de verificação ordenadas referenciando IDs de `AppFeature` do catálogo, formatos opcionais de entrada/saída, parâmetros de nova tentativa, um grafo visual `visitaFlow` e notificações de conclusão.

Criar uma configuração não executa consultas e não consome créditos. Observe que este endpoint retorna HTTP `200` (não `201`) com a configuração salva em `data`. A validação de schema é tratada diretamente pelo Mongoose, portanto campos inválidos ou ausentes retornam `422 UnprocessableEntity`.

### Endpoint

```
POST https://api.verifik.co/v2/batch-configurations
```

Também acessível pelo proxy do Smart-Agent em `https://ai.verifik.co/v2/batch-configurations` usando seu próprio cabeçalho `Authorization: Bearer <VERIFIK_JWT>` por cliente. A execução compartilhada via x402 é bloqueada com `403 Forbidden`.

### Cabeçalhos

| Nome | Valor |
| ---- | ----- |
| Content-Type | `application/json` |
| Authorization | `Bearer <VERIFIK_JWT>` |

O token deve ser um **JWT de cliente**. Credenciais ausentes ou inválidas retornam `401 Unauthorized`.

### Corpo

| Nome | Tipo | Obrigatório | Descrição |
| ---- | ---- | ----------- | --------- |
| `name` | string | Sim | Nome de exibição da configuração. Aparado, máximo de `150` caracteres. |
| `country` | string | Sim | Escopo de país da configuração. Aparado e convertido para maiúsculas pelo servidor (por exemplo, `CO`). |
| `steps` | object[] | Sim | Array ordenado de objetos de etapa de verificação (veja os campos de `steps[]` abaixo). |
| `description` | string | Não | Resumo opcional do fluxo de trabalho. Máximo de `800` caracteres. |
| `executor` | string | Não | Alvo de execução: `queue`, `featureRunner` ou `browser`. O padrão é `featureRunner` (persistido como `browser`, enquanto o executor headless roda via `FeatureRunner`). |
| `inputFormat` | string | Não | Formato padrão de entrada: `csv`, `jsonl` ou `xlsx`. O padrão é `csv`. |
| `outputFormat` | string | Não | Formato padrão de saída: `csv`, `jsonl` ou `xlsx`. O padrão é `csv`. |
| `mergeStrategy` | string | Não | Estratégia de execução de etapas: `sequential`, `parallel-independent` ou `parallel-with-fallback`. O padrão é `sequential`. |
| `notification` | object | Não | Configurações de notificação de conclusão (`webhookUrl` e `emailOnCompletion`). Veja os campos de `notification` abaixo. |
| `scheduleExpression` | string | Não | Expressão de agendamento opcional para execuções automatizadas. |
| `preferredReportTemplate` | string | Não | ObjectId do `SmartReportTemplate` vinculado como template de relatório padrão para lotes desta configuração. |
| `visitaFlow` | object | Não | Grafo visual de nós que define o encadeamento de etapas. Quaisquer placeholders `{{results.N.field}}` são excluídos das entradas manuais no schema de entrada derivado. |
| `isActive` | boolean | Não | Se a configuração está ativa. O padrão é `true`. |

#### Campos do objeto `steps[]`

| Nome | Tipo | Obrigatório | Descrição |
| ---- | ---- | ----------- | --------- |
| `appFeature` | string | Sim | ObjectId do `AppFeature` a ser executado nesta etapa. |
| `sequence` | number | Sim | Ordem de execução da etapa baseada em 1 (`>= 1`). |
| `enabled` | boolean | Não | Se esta etapa é executada durante a execução do lote. O padrão é `true`. |
| `parameterDefaults` | object | Não | Valores de parâmetros estáticos ou expressões `{{results.N.field}}` fixados nesta etapa. O padrão é `{}`. |
| `queryMode` | string | Não | Seletor opcional de grupo de dependências quando o recurso suporta múltiplos modos de consulta. |
| `inputFieldMapping` | object | Não | Mapeia nomes de colunas de entrada para nomes de parâmetros da API (`inputColumn -> apiParam`). O padrão é `{}`. |
| `outputFieldsToKeep` | string[] | Não | Subconjunto de campos de saída a reter nos resultados tabulares. O padrão é `[]`. |
| `maxRetries` | number | Não | Máximo de novas tentativas em falha transitória da etapa (`>= 0`). O padrão é `3`. |
| `retryDelayBaseSeconds` | number | Não | Atraso base de backoff em segundos (`>= 1`). O padrão é `4`. |
| `timeoutSeconds` | number | Não | Tempo limite de execução da etapa em segundos (`>= 5`). O padrão é `30`. |

#### Campos do objeto `notification`

| Nome | Tipo | Obrigatório | Descrição |
| ---- | ---- | ----------- | --------- |
| `webhookUrl` | string | Não | Endpoint HTTPS a notificar na conclusão do lote. Informar `webhookUrl` sincroniza automaticamente um Webhook Verifik ativo para o seu cliente. |
| `emailOnCompletion` | string[] | Não | Lista de endereços de e-mail destinatários a notificar quando um lote termina. |

### Notas

- O sucesso retorna HTTP **`200`** (não `201`) com o documento criado em `data`.
- Este endpoint não possui middleware Joi; a validação do schema Mongoose impõe campos obrigatórios e restrições numéricas, retornando `422 UnprocessableEntity` em caso de falha.
- Quando `executor` é `"featureRunner"` (o padrão), o servidor persiste `"browser"` no documento de configuração enquanto o executor headless continua executando via `FeatureRunner`.
- Definir `notification.webhookUrl` cria ou sincroniza automaticamente um Webhook Verifik ativo para o seu cliente.
- Em seguida, chame [Obter schema de entrada da configuração](/verifik-pt/smart-reports/retrieve-configuration-input-schema) para inspecionar os campos derivados e o `exampleInput` antes de executar um relatório.
