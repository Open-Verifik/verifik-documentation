Inicie a execução de um `SmartBatch` existente. O lote deve estar atualmente no status `"draft"`, `"pending"` ou `"cancelled"`; qualquer outro status falha com `400 BadRequest` (`batch_not_in_startable_state`).

Antes de iniciar, o servidor valida se todas as etapas habilitadas na `BatchConfiguration` vinculada estão liberadas na sua conta de cliente (`409 endpoints_not_in_account` se algum recurso estiver ausente), define `status: "processing"` e `startedAt`, e retorna o `SmartBatch` atualizado.

### Endpoint

```text
POST https://api.verifik.co/v2/smart-batches/{id}/start
```

Este endpoint também é acessível pelo proxy do Smart-Agent em `https://ai.verifik.co/v2/smart-batches/{id}/start` usando seu próprio `Authorization: Bearer <VERIFIK_JWT>` por cliente. A execução compartilhada via x402 é bloqueada com `403 Forbidden`.

### Cabeçalhos

| Nome            | Valor                  | Descrição                                      |
| --------------- | ---------------------- | ---------------------------------------------- |
| `Content-Type`  | `application/json`     | Formato do payload da requisição.              |
| `Authorization` | `Bearer <VERIFIK_JWT>` | JWT com escopo de cliente (`authUser.clientId`). |

### Parâmetros

| Nome | Tipo   | Obrigatório | Descrição |
| ---- | ------ | ----------- | --------- |
| `id` | string | Sim         | ObjectId do `SmartBatch` a iniciar. |

### Notas

- Apenas lotes nos status `"draft"`, `"pending"` ou `"cancelled"` podem ser iniciados; lotes pausados devem usar [Retomar um Smart Batch](/verifik-pt/smart-reports/resume-a-smart-batch).
- Reiniciar um lote `"cancelled"` limpa `completedAt` e redefine quaisquer linhas `"processing"` de volta para `"pending"`.
- Verifique as cobranças de créditos projetadas antes usando [Estimar custo do Smart Batch](/verifik-pt/smart-reports/estimate-smart-batch-cost) e acompanhe a execução com [Obter progresso do Smart Batch](/verifik-pt/smart-reports/get-smart-batch-progress).
