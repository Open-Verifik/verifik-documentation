Entregue um `SmartReport` por e-mail com relatórios PDF anexados. Você pode deixar a Verifik renderizar o PDF para uma única linha (`rowIndex`) ou para todas as linhas (`sendAll: true`, até `50` linhas), ou fornecer payloads pré-renderizados `printHtml`, `pdfBase64` ou `pdfFiles`.

O envio de um e-mail registra `emailDelivery` no documento `SmartReport` e emite `smart_batch_report_sent` em caso de sucesso ou `smart_batch_report_delivery_failed` em caso de falha na entrega.

### Endpoint

```
POST https://api.verifik.co/v2/smart-reports/{id}/send-email
```

Este endpoint aceita payloads JSON de até **64 MB**. Ele também pode ser acessado pelo proxy do Smart-Agent em `https://ai.verifik.co/v2/smart-reports/{id}/send-email` usando o seu próprio cabeçalho `Authorization: Bearer <VERIFIK_JWT>` por cliente. A execução compartilhada via x402 é bloqueada com `403 Forbidden`.

### Cabeçalhos

| Nome            | Valor                  | Descrição                                                   |
| --------------- | ---------------------- | ----------------------------------------------------------- |
| `Content-Type`  | `application/json`     | Formato do payload da requisição (limite de 64 MB).         |
| `Authorization` | `Bearer <VERIFIK_JWT>` | JWT com escopo de cliente (`authUser.clientId`).            |

### Parâmetros

| Nome | Tipo   | Obrigatório | Descrição |
| ---- | ------ | ----------- | --------- |
| `id` | string | **Sim**     | ObjectId do `SmartReport`. |

### Corpo

| Nome         | Tipo     | Obrigatório | Descrição |
| ------------ | -------- | ----------- | --------- |
| `recipients` | string[] | **Sim**     | Array de endereços de e-mail válidos dos destinatários (mínimo de `1`). |
| `subject`    | string   | Não         | Linha de assunto personalizada do e-mail. |
| `language`   | string   | Não         | Idioma do texto do e-mail: `"en"` ou `"es"`. Padrão `"es"`. |
| `rowIndex`   | number   | Não         | Índice da linha em base zero para renderizar e anexar quando `sendAll` não estiver habilitado. |
| `sendAll`    | boolean  | Não         | Quando `true`, envia até `50` linhas (`MAX_SEND_ALL_ROWS`), anexando 1 PDF por linha quando o lote tiver mais de 1 linha. |
| `engine`     | string   | Não         | Motor de renderização de PDF: `"pdfkit"` ou `"puppeteer"`. |
| `printHtml`  | string   | Não         | String HTML pré-renderizada (máximo de `64000000` caracteres) para converter e anexar. |
| `pdfBase64`  | string   | Não         | String PDF codificada em base64 pré-renderizada (máximo de `64000000` caracteres) para anexar diretamente. |
| `pdfFiles`   | object[] | Não         | Array de até `200` objetos de anexo (`{ filename, pdfBase64 }`), onde `filename` (máximo de `80` caracteres) e `pdfBase64` (máximo de `64000000` caracteres) são obrigatórios para cada item. |

#### Regras de anexos e entrega em lote

- **Limite de `sendAll`**: Enviar todas as linhas de um lote aceita até `50` linhas (`MAX_SEND_ALL_ROWS`). Exceder 50 linhas falha com `409 Conflict` (`send_all_limit`). Quando um lote contém mais de 1 linha, cada linha é anexada como seu próprio arquivo PDF.
- **Payloads pré-renderizados**: Forneça `pdfFiles` (até `200` itens), `pdfBase64` ou `printHtml` quando sua integração já tiver renderizado anexos personalizados. Dados de PDF corrompidos retornam `500` (`invalid_pdf`), e requisições que resultam em zero anexos retornam `409 Conflict` (`no_pdf_attachments`).
- **Resposta do resultado da entrega**: Se o transporte de e-mail falhar após o sucesso da validação e da preparação do PDF, o endpoint retorna HTTP `200 OK` com `"success": false`, `"messageId": null` e um campo `"error"`, enquanto registra `emailDelivery` e emite `smart_batch_report_delivery_failed`.

#### Códigos de erro

| Status | Código / Tipo de erro | Causa |
| ------ | --------------------- | ----- |
| `401` | `Unauthorized` | JWT ausente ou inválido. |
| `403` | `Forbidden` | Tentativa de execução compartilhada via x402; use o seu próprio JWT por cliente. |
| `404` | `not_found` | O ID do relatório não existe ou pertence a outro cliente. |
| `404` | `template_not_found` | O template vinculado não foi encontrado. |
| `409` | `MissingParameter` | A validação Joi falhou (por exemplo, `recipients` ausente ou inválido). |
| `409` | `send_all_limit` | `sendAll: true` foi solicitado em um lote com mais de `50` linhas (`MAX_SEND_ALL_ROWS`). |
| `409` | `no_pdf_attachments` | Nenhum anexo PDF pôde ser resolvido ou renderizado para a requisição. |
| `409` | `row_not_found` | O `rowIndex` solicitado não existe no lote. |
| `422` | `UnprocessableEntity` | Erro de validação do Mongoose. |
| `500` | `invalid_pdf` | O payload `pdfBase64` ou `pdfFiles` informado não é um PDF válido. |

### Webhooks e integração MCP

- **Webhooks**: Emite automaticamente `smart_batch_report_sent` quando a entrega é bem-sucedida ou `smart_batch_report_delivery_failed` quando a entrega falha, e registra `emailDelivery` no `SmartReport`. Veja [Webhooks do SmartReports](/verifik-pt/resources/smart-reports-webhooks).
- **Equivalente MCP**: Agentes de IA podem enviar e-mails de relatório por meio da ferramenta MCP `smart_report_send_email`. Veja [MCP e Agentes de IA](/verifik-pt/smart-reports/mcp-and-ai-agents).

### Notas

- Sempre inspecione `success` no corpo `200 OK`, pois erros de transporte de e-mail retornam `success: false` com `messageId: null` e `error` em vez de um código de status diferente de 200.
- Se quiser executar etapas de verificação, gerar PDFs e enviar por e-mail em uma única chamada, use [Executar um Smart Report](/verifik-pt/smart-reports/run-a-smart-report).
