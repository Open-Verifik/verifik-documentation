Pause um `SmartBatch` ativo (e qualquer execução `FeatureRunner` anexada) sem perder os resultados já gravados para as linhas concluídas. Os workers param de reivindicar as linhas restantes até que você retome o lote.

Lotes de fila e navegador devem estar no status `"processing"` ou `"pending"` (`400 batch_not_pausable` caso contrário). Lotes apoiados por uma execução `FeatureRunner` exigem que a execução esteja no status `"queued"` ou `"processing"` (`400 run_not_pausable` caso contrário). Pausar não consome créditos.

### Endpoint

```text
POST https://api.verifik.co/v2/smart-batches/{id}/pause
```

Este endpoint também é acessível pelo proxy do Smart-Agent em `https://ai.verifik.co/v2/smart-batches/{id}/pause` usando seu próprio `Authorization: Bearer <VERIFIK_JWT>` por cliente. A execução compartilhada via x402 é bloqueada com `403 Forbidden`.

### Cabeçalhos

| Nome            | Valor                  | Descrição                                      |
| --------------- | ---------------------- | ---------------------------------------------- |
| `Content-Type`  | `application/json`     | Formato do payload da requisição.              |
| `Authorization` | `Bearer <VERIFIK_JWT>` | JWT com escopo de cliente (`authUser.clientId`). |

### Parâmetros

| Nome | Tipo   | Obrigatório | Descrição |
| ---- | ------ | ----------- | --------- |
| `id` | string | Sim         | ObjectId do `SmartBatch` a pausar. |

### Notas

- Para pausar um lote programaticamente, sempre use este endpoint em vez de `PUT /v2/smart-batches/{id}` (que não aceita `"paused"`).
- Um lote apoiado por `FeatureRunner` retorna `400 BadRequest` com `run_not_pausable` se sua execução não estiver no status `"queued"` ou `"processing"`.
- Continue a execução mais tarde usando [Retomar um Smart Batch](/verifik-pt/smart-reports/resume-a-smart-batch), ou encerre permanentemente com [Cancelar um Smart Batch](/verifik-pt/smart-reports/cancel-a-smart-batch).
