Carregue uma Check List por id. A lista deve pertencer ao cliente do JWT. Um ObjectId inválido, uma lista inexistente ou uma lista de outro cliente devolve `404`.

Esta chamada não executa consultas e não gasta créditos. Use `featureCodes` do documento para chamar cada API do catálogo você mesmo.

### Endpoint

```
GET https://api.verifik.co/v2/check-lists/{id}
```

Devolve a lista guardada: `name`, `countries`, `domains`, `featureCodes` e `status`. Use esses códigos com as URLs correspondentes do SmartCheck / catálogo. Não há ação de executar checklist neste caminho.

### Headers

| Name          | Value              |
| ------------- | ------------------ |
| Content-Type  | `application/json` |
| Authorization | `Bearer <token>`   |

O token deve ser um **JWT de cliente**. Um token sem `clientId` devolve `403`.

### Parameters

| Name | Type   | Required | Description                          |
| ---- | ------ | -------- | ------------------------------------ |
| `id` | string | Yes      | ObjectId da Check List da criação ou da listagem. |

### Notes

- ObjectIds inválidos e listas de outros clientes devolvem `404` (`check_list_not_found`).
- A resposta não inclui uma URL de retomada hospedada nem uma URL de lote. A Check List só guarda a combinação.
- Para alterar campos, use [Atualizar uma checklist](/verifik-pt/check-list/update-a-check-list). Para removê-la, use [Apagar uma checklist](/verifik-pt/check-list/delete-a-check-list).
- Executar um código de `featureCodes` é uma chamada normal ao catálogo e gasta créditos aí. Veja SmartCheck.
