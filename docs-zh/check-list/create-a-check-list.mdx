在已认证客户上创建一份 Check List。`name` 为必填。国家、领域和功能代码在创建时可选 — 之后可用 [更新清单](/verifik-zh/check-list/update-a-check-list) 添加服务。

保存列表不会执行查询，也不会消耗积分。在 Smart-Agent 中，创建后会回到仪表盘；此 API 会立即返回新文档。

### Endpoint

```
POST https://api.verifik.co/v2/check-lists
```

创建由 JWT 上客户拥有的列表。响应的 `data` 对象包含 `_id` — 请保存它，供之后的 GET、PUT 和 DELETE 使用。默认 `status` 为 `draft`。

### Headers

| Name          | Value              |
| ------------- | ------------------ |
| Content-Type  | `application/json` |
| Authorization | `Bearer <token>`   |

令牌必须是**客户 JWT**。没有 `clientId` 的令牌返回 `403`。

### Body

| Name           | Type     | Required | Description                                                                 |
| -------------- | -------- | -------- | --------------------------------------------------------------------------- |
| `name`         | string   | Yes      | 显示名称。去首尾空格，1–150 个字符。                                    |
| `countries`    | string[] | No       | 你运营的国家名称（例如 `Colombia`）。重复项会被去掉。默认 `[]`。 |
| `domains`      | string[] | No       | 可选页签：`people`、`vehicles`、`businesses`。默认 `[]`。            |
| `featureCodes` | string[] | No       | 要保存在列表上的 AppFeature `code` 值。默认 `[]`。                 |
| `status`       | string   | No       | `draft`（默认）或 `active`。仅整理标签 — 两者行为相同。   |

未知的 `featureCodes` 会失败。国家与 `countries` 不符的服务会失败，除非该服务是全球范围或 `countries` 为空。

### Notes

- `name` 是唯一必填字段。你可以创建空列表，稍后再添加 `featureCodes`。
- 国家按你发送的原文存储（例如 `Colombia`）。它们不是 ISO 代码。
- `status` 不会改变服务器行为。草稿和启用的列表都能用。
- 未知的 `domains` 值会校验失败。允许的值：`people`、`vehicles`、`businesses`。
- 创建列表不消耗积分。执行已保存的服务是普通的目录调用。
- 没有“执行清单”接口。见 [Check List](/verifik-zh/check-list) 和 [SmartBatch](/verifik-zh/smart-batch)。
