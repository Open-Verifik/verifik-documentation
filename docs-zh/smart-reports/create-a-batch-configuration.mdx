在你的已认证客户账户下创建一个自定义 `BatchConfiguration`。你可以定义目标 `country`、引用目录 `AppFeature` ID 的有序核验 `steps`、可选的输入/输出格式、重试参数、`visitaFlow` 可视化节点图以及完成通知。

创建配置不会执行任何核验，也不会消耗积分。请注意，此接口成功时返回 HTTP `200`（而非 `201`），并在 `data` 中返回已保存的配置对象。模式校验由 Mongoose 直接处理，因此缺少字段或字段无效时将返回 `422 UnprocessableEntity`。

### 接口

```
POST https://api.verifik.co/v2/batch-configurations
```

也可以通过 Smart-Agent 代理 `https://ai.verifik.co/v2/batch-configurations` 访问，并使用你自己的客户专属 `Authorization: Bearer <VERIFIK_JWT>` 请求头。共享 x402 执行会被拒绝并返回 `403 Forbidden`。

### 请求头

| 名称 | 值 |
| ---- | -- |
| Content-Type | `application/json` |
| Authorization | `Bearer <VERIFIK_JWT>` |

令牌必须是**客户 JWT**。缺少凭证或凭证无效将返回 `401 Unauthorized`。

### 请求体

| 名称 | 类型 | 必填 | 描述 |
| ---- | ---- | ---- | ---- |
| `name` | string | 是 | 配置的显示名称。去除首尾空格，最多 `150` 个字符。 |
| `country` | string | 是 | 配置适用的国家范围。服务器会自动去除首尾空格并转为大写（例如 `CO`）。 |
| `steps` | object[] | 是 | 有序的核验步骤对象数组（见下方 `steps[]` 字段）。 |
| `description` | string | 否 | 可选的工作流摘要说明。最多 `800` 个字符。 |
| `executor` | string | 否 | 执行目标：`queue`、`featureRunner` 或 `browser`。默认为 `featureRunner`（持久化存储为 `browser`，而无头运行器通过 `FeatureRunner` 执行）。 |
| `inputFormat` | string | 否 | 默认输入格式：`csv`、`jsonl` 或 `xlsx`。默认为 `csv`。 |
| `outputFormat` | string | 否 | 默认输出格式：`csv`、`jsonl` 或 `xlsx`。默认为 `csv`。 |
| `mergeStrategy` | string | 否 | 步骤执行策略：`sequential`、`parallel-independent` 或 `parallel-with-fallback`。默认为 `sequential`。 |
| `notification` | object | 否 | 完成通知设置（`webhookUrl` 和 `emailOnCompletion`）。见下方 `notification` 字段。 |
| `scheduleExpression` | string | 否 | 用于自动运行的可选定时调度表达式。 |
| `preferredReportTemplate` | string | 否 | 关联为该配置下批次默认报告模板的 `SmartReportTemplate` ObjectId。 |
| `visitaFlow` | object | 否 | 定义步骤链的可视化节点图。任何 `{{results.N.field}}` 占位符都会从派生的输入模式（input schema）的手动输入字段中排除。 |
| `isActive` | boolean | 否 | 配置是否处于启用状态。默认为 `true`。 |

#### `steps[]` 对象字段

| 名称 | 类型 | 必填 | 描述 |
| ---- | ---- | ---- | ---- |
| `appFeature` | string | 是 | 此步骤要执行的 `AppFeature` ObjectId。 |
| `sequence` | number | 是 | 从 1 开始的步骤执行顺序（`>= 1`）。 |
| `enabled` | boolean | 否 | 批次执行期间是否运行此步骤。默认为 `true`。 |
| `parameterDefaults` | object | 否 | 固定在此步骤上的静态参数值或 `{{results.N.field}}` 表达式。默认为 `{}`。 |
| `queryMode` | string | 否 | 当该功能支持多种查询模式时，可选的依赖组选择器。 |
| `inputFieldMapping` | object | 否 | 将输入列名映射为 API 参数名（`inputColumn -> apiParam`）。默认为 `{}`。 |
| `outputFieldsToKeep` | string[] | 否 | 在表格结果中保留的输出字段子集。默认为 `[]`。 |
| `maxRetries` | number | 否 | 步骤发生瞬时失败时的最大重试次数（`>= 0`）。默认为 `3`。 |
| `retryDelayBaseSeconds` | number | 否 | 退避重试基础延迟秒数（`>= 1`）。默认为 `4`。 |
| `timeoutSeconds` | number | 否 | 单步执行超时秒数（`>= 5`）。默认为 `30`。 |

#### `notification` 对象字段

| 名称 | 类型 | 必填 | 描述 |
| ---- | ---- | ---- | ---- |
| `webhookUrl` | string | 否 | 批次完成时接收通知的 HTTPS 端点。提供 `webhookUrl` 会自动为你的客户账户同步创建一个启用状态的 Verifik Webhook。 |
| `emailOnCompletion` | string[] | 否 | 批次完成时接收通知的收件人邮箱地址列表。 |

### 注意事项

- 成功时返回 HTTP **`200`**（而非 `201`），并在 `data` 中包含已创建的文档。
- 此接口没有 Joi 中间件；Mongoose 模式校验会强制检查必填字段和数值约束，校验失败时返回 `422 UnprocessableEntity`。
- 当 `executor` 为 `"featureRunner"`（默认值）时，服务器会在配置文档上持久化保存 `"browser"`，而无头运行器仍会继续通过 `FeatureRunner` 执行。
- 设置 `notification.webhookUrl` 会自动为你的客户账户创建或同步一个启用状态的 Verifik Webhook。
- 接下来，请调用[获取配置输入模式](/verifik-zh/smart-reports/retrieve-configuration-input-schema)，在运行报告前查看派生字段和 `exampleInput`。
