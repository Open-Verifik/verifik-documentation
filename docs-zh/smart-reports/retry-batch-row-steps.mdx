仅清除并重新入队 `SmartBatch` 单行（`rowIndex`）上的指定 `sequences`，同时保持该行所有其他步骤的已存储输出以及所有其他行完全不变。`rowIndex` 和 `sequences` 均为必填项。

如果批次、目标行、底层 `FeatureRunner` 运行记录或运行项当前正在处理中，服务器将拒绝该请求并返回 `409 Conflict`（`batch_is_processing`、`row_is_processing`、`run_is_processing`、`item_is_processing`）。

### 接口

```text
POST https://api.verifik.co/v2/smart-batches/{id}/retry-steps
```

此接口也可通过 Smart-Agent 代理 `https://ai.verifik.co/v2/smart-batches/{id}/retry-steps` 访问，需使用你自己的客户专属 `Authorization: Bearer <VERIFIK_JWT>`。共享 x402 执行会被拒绝并返回 `403 Forbidden`。

### 请求头

| 名称            | 值                     | 描述                                     |
| --------------- | ---------------------- | ---------------------------------------- |
| `Content-Type`  | `application/json`     | 请求载荷格式。                           |
| `Authorization` | `Bearer <VERIFIK_JWT>` | 客户作用域的 JWT（`authUser.clientId`）。 |

### 参数

| 名称 | 类型   | 必填 | 描述 |
| ---- | ------ | ---- | ---- |
| `id` | string | 是   | `SmartBatch` ObjectId。 |

### 请求体

| 名称        | 类型      | 必填 | 描述 |
| ----------- | --------- | ---- | ---- |
| `rowIndex`  | integer   | 是   | 要部分重试的行在批次中从 `0` 开始的索引（`>= 0`）。 |
| `sequences` | integer[] | 是   | 要在该行上清除并重新执行的步骤序号数组（`>= 0`，最少 `1` 项，最多 `200` 项）。 |

未知请求体键或缺少必填字段将被 Joi 校验拒绝，并返回 `409 MissingParameter`。

### 注意事项

- 仅清除 `rowIndex` 上指定 `sequences` 已存储的 `results` 和 `errors`；其他所有步骤序号的结果将保持不变。
- 可能的 `409 Conflict` 原因包括 `batch_is_processing`、`row_is_processing`、`run_is_processing` 和 `item_is_processing`。
- 传入无效或空的步骤序号引用将返回 `400 BadRequest`（`retry_steps_invalid`）。
- 若要重试整个批次中所有失败或部分完成的行，请使用[重试失败的 Smart Batch 行](/verifik-zh/smart-reports/retry-failed-batch-rows)。
