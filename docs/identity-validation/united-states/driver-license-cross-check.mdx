# United States — Driver License Barcode Cross-Check

The **United States Driver License Cross-Check API** combats physical document fraud and synthetic identity fabrication by mathematically correlating data from the physical front of an ID with the encoded AAMVA PDF417 2D barcode on the reverse side.

In identity fraud schemes, bad actors frequently alter visual front-side text or photos while leaving the reverse barcode untouched, or fabricate mismatched barcodes. This service performs subfield-by-subfield matching across license number, full name, date of birth, issuing jurisdiction, and expiration date, producing deterministic field match scores, discrepancy alerts, and an overall authenticity verdict.

---

## API Reference

### Endpoint

```http
POST https://api.verifik.co/v2/usa/driver-license/cross-check
```

Cross-examine user-supplied or front-OCR identity fields against the cryptographic and structured payload of the rear AAMVA barcode.

### Headers

| Name | Value | Description |
| :--- | :--- | :--- |
| Content-Type | `application/json` | Request payload format |
| Accept | `application/json` | Response format |
| Authorization | `Bearer <token>` | Client JWT authentication token |

### Parameters

| Parameter | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `licenseNumber` | string | **Yes** | License or document number printed on front of card (e.g., `D1234567`). |
| `firstName` | string | **Yes** | Subject first name (e.g., `JOHN`). |
| `lastName` | string | **Yes** | Subject last name or surname (e.g., `DOE`). |
| `backImage` | string | **Conditional** | Base64-encoded image or public HTTPS URL of rear barcode. Required if `rawBarcode` is omitted. |
| `rawBarcode` | string | **Conditional** | Raw ANSI/AAMVA PDF417 barcode text payload. Required if `backImage` is omitted. |
| `dateOfBirth` | string | No | Date of birth in `YYYY-MM-DD` format (e.g., `1990-01-15`). |
| `state` | string | No | Expected two-letter US state abbreviation (e.g., `CA`). |

### Notes

- **Fraud & Tampering Defense:** Attackers often alter front card details (such as names or birth years to bypass age restrictions) using photo editing software without re-encoding the complex 2D barcode on the reverse side. Cross-checking catches 100% of these front-only alterations.
- **Verdict Classifications:** The `verdict` property evaluates to `"confirmed"` when all critical fields meet high-confidence thresholds, `"discrepancy"` when one or more key fields diverge, or `"invalid_barcode"` if the reverse barcode payload is malformed or unreadable.
- **Deterministic Field Scoring:** `fieldScores` provides granular confidence values from `0.0` (complete mismatch) to `1.0` (exact canonical match) for each compared identifier.
