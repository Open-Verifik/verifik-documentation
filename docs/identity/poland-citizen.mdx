# Poland — Citizen Identity & Sole Proprietor Verification (KYC)

The **Poland Citizen Identity & Sole Proprietor Verification** checks a person or sole proprietor against the official source for this identifier (NIP). Send that number as `documentNumber`. Use it when onboarding needs the legal name, registration status, and the identity attributes the source publishes.

`documentNumber` is required. `documentType` defaults to `NIP`. Omit it to keep that default, or send `NIP` explicitly.

## What the registry returns

- Legal name of the person or sole proprietor
- Registration status
- Identifier that was queried
- Official identity attributes published by the source

## Use cases

- Confirm a sole proprietor or individual registrant in Poland during onboarding.
- Match the legal name on file to the official identifier.
- Store the registration status and the identity attributes the official source publishes.

---

## API Reference

### Endpoint

```http
GET https://api.verifik.co/v2/pl/citizen
```

Query the official identity and sole-proprietor source of Poland with `documentNumber`. `documentType` selects the identifier family (NIP). A successful payload includes the legal name, registration status, the identifier you sent, and the official identity attributes the source publishes. Use it for KYC onboarding of a person or sole proprietor. The sample below shows those fields. Live values come from the official source.

### Headers

| Name | Value | Description |
| :--- | :--- | :--- |
| Content-Type | `application/json` | Request payload format |
| Accept | `application/json` | Response format |
| Authorization | `Bearer <your_token>` | Client JWT authentication token |

### Parameters

| Name | Type | Required | Example | Description |
| :--- | :--- | :--- | :--- | :--- |
| `documentNumber` | string | **Yes** | `5252344078` | Official identity or taxpayer number for the person or sole proprietor (NIP). |
| `documentType` | string | No | `NIP` | Document type identifier. Defaults to `NIP`. |

### Notes

- **Identifier format.** On this route the identifier is the 10-digit NIP. documentType defaults to NIP. Send digits only, without spaces or dashes.
- Document type identifier. Defaults to `NIP`.
- The status label in the sample illustrates the field. The live registry returns its own label, which may be a local-language status.
- Send `documentNumber` and, when you need to name the identifier family, `documentType`. Those are the client parameters for this route.
- The JSON sample is an illustration of the fields above. A live call returns the registry record for the identifier you send.

## Sandbox

With the account in sandbox mode, the same parameters exercise this route. The table describes the response documented for each case.

| Scenario | Parameters | Result |
| :--- | :--- | :--- |
| **Identifier on file** | `documentType: "NIP"`, `documentNumber: "5252344078"` | 200 with legal name, status, identifier, and address or identity attributes when the source holds the number. |
| **Missing documentNumber** | Omit `documentNumber` | 409 `MissingParameter` when `documentNumber` is omitted. |
| **Unknown number** | `documentNumber: "000000000"` | 404 `NotFound` when the registry has no record for that number. |

401 when the bearer token is missing or rejected.
