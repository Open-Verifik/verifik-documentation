Create a custom `BatchConfiguration` on your authenticated client account. Define the target `country`, ordered verification `steps` referencing catalog `AppFeature` IDs, optional input/output formats, retry parameters, a `visitaFlow` visual graph, and completion notifications.

Creating a configuration does not execute any checks and does not consume credits. Note that this endpoint returns HTTP `200` (not `201`) with the saved configuration in `data`. Schema validation is handled directly by Mongoose, so invalid or missing fields return `422 UnprocessableEntity`.

### Endpoint

```
POST https://api.verifik.co/v2/batch-configurations
```

Also reachable via the Smart-Agent proxy at `https://ai.verifik.co/v2/batch-configurations` using your own per-client `Authorization: Bearer <VERIFIK_JWT>` header. Shared x402 execution is blocked with `403 Forbidden`.

### Headers

| Name | Value |
| ---- | ----- |
| Content-Type | `application/json` |
| Authorization | `Bearer <VERIFIK_JWT>` |

The token must be a **client JWT**. Missing or invalid credentials return `401 Unauthorized`.

### Body

| Name | Type | Required | Description |
| ---- | ---- | -------- | ----------- |
| `name` | string | Yes | Display name for the configuration. Trimmed, maximum `150` characters. |
| `country` | string | Yes | Country scope for the configuration. Trimmed and uppercased by the server (for example, `CO`). |
| `steps` | object[] | Yes | Ordered array of verification step objects (see `steps[]` fields below). |
| `description` | string | No | Optional summary of the workflow. Maximum `800` characters. |
| `executor` | string | No | Execution target: `queue`, `featureRunner`, or `browser`. Defaults to `featureRunner` (persisted as `browser`, while the headless runner executes via `FeatureRunner`). |
| `inputFormat` | string | No | Default input format: `csv`, `jsonl`, or `xlsx`. Defaults to `csv`. |
| `outputFormat` | string | No | Default output format: `csv`, `jsonl`, or `xlsx`. Defaults to `csv`. |
| `mergeStrategy` | string | No | Step execution strategy: `sequential`, `parallel-independent`, or `parallel-with-fallback`. Defaults to `sequential`. |
| `notification` | object | No | Completion notification settings (`webhookUrl` and `emailOnCompletion`). See `notification` fields below. |
| `scheduleExpression` | string | No | Optional schedule expression for automated runs. |
| `preferredReportTemplate` | string | No | `SmartReportTemplate` ObjectId linked as the default report template for batches under this configuration. |
| `visitaFlow` | object | No | Visual node graph defining step chaining. Any `{{results.N.field}}` placeholders are excluded from manual inputs in the derived input schema. |
| `isActive` | boolean | No | Whether the configuration is active. Defaults to `true`. |

#### `steps[]` object fields

| Name | Type | Required | Description |
| ---- | ---- | -------- | ----------- |
| `appFeature` | string | Yes | `AppFeature` ObjectId to execute for this step. |
| `sequence` | number | Yes | 1-based step execution order (`>= 1`). |
| `enabled` | boolean | No | Whether this step runs during batch execution. Defaults to `true`. |
| `parameterDefaults` | object | No | Static parameter values or `{{results.N.field}}` expressions pinned to this step. Defaults to `{}`. |
| `queryMode` | string | No | Optional dependency group selector when the feature supports multiple lookup modes. |
| `inputFieldMapping` | object | No | Maps input column names to API parameter names (`inputColumn -> apiParam`). Defaults to `{}`. |
| `outputFieldsToKeep` | string[] | No | Subset of output fields to retain in tabular results. Defaults to `[]`. |
| `maxRetries` | number | No | Maximum retry attempts on transient step failure (`>= 0`). Defaults to `3`. |
| `retryDelayBaseSeconds` | number | No | Base backoff delay in seconds (`>= 1`). Defaults to `4`. |
| `timeoutSeconds` | number | No | Step execution timeout in seconds (`>= 5`). Defaults to `30`. |

#### `notification` object fields

| Name | Type | Required | Description |
| ---- | ---- | -------- | ----------- |
| `webhookUrl` | string | No | HTTPS endpoint to notify on batch completion. Supplying `webhookUrl` automatically syncs an active Verifik Webhook for your client. |
| `emailOnCompletion` | string[] | No | List of recipient email addresses to notify when a batch finishes. |

### Notes

- Success returns HTTP **`200`** (not `201`) with the created document in `data`.
- This endpoint has no Joi middleware; Mongoose schema validation enforces required fields and numeric constraints, returning `422 UnprocessableEntity` on failure.
- When `executor` is `"featureRunner"` (the default), the server persists `"browser"` on the configuration document while the headless runner continues executing via `FeatureRunner`.
- Setting `notification.webhookUrl` automatically creates or synchronizes an active Verifik Webhook for your client.
