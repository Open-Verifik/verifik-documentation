Create a `SmartBatch` linked to an existing `BatchConfiguration`. You supply a display `name` and at least one input row in `rows`. Creating the batch persists the input rows with `status: "draft"` and does not execute catalog steps or spend credits until execution starts.

Each entry in `rows` accepts either a wrapped object (`{ rowIndex?, inputData }`) or a flat object (`{ rowIndex?, ...inputFields }`), which the validation layer normalizes into `{ rowIndex, inputData }`. Do **not** include `status`, `results`, or `errors` on create.

### Endpoint

```text
POST https://api.verifik.co/v2/smart-batches
```

This endpoint is also reachable through the Smart-Agent proxy at `https://ai.verifik.co/v2/smart-batches` using your own per-client `Authorization: Bearer <VERIFIK_JWT>`. Shared x402 execution is blocked with `403 Forbidden`.

### Headers

| Name            | Value                  | Description                              |
| --------------- | ---------------------- | ---------------------------------------- |
| `Content-Type`  | `application/json`     | Request payload format.                  |
| `Authorization` | `Bearer <VERIFIK_JWT>` | Client-scoped JWT (`authUser.clientId`). |

### Body

| Name                 | Type     | Required | Description |
| -------------------- | -------- | -------- | ----------- |
| `batchConfiguration` | string   | Yes      | `BatchConfiguration` ObjectId defining the workflow steps. |
| `name`               | string   | Yes      | Batch display name. Maximum `150` characters. |
| `executor`           | string   | No       | Execution mode: `"queue"`, `"featureRunner"`, or `"browser"`. When derived from `batchConfiguration`, it is normalized to `"queue"` or `"browser"`. |
| `source`             | string   | No       | Originating product identifier: `"smart_batch"` (default) or `"smart_fleet"`. |
| `rows`               | object[] | Yes      | Array of at least `1` row (`min 1`). Accepts wrapped `{ rowIndex?, inputData }` or flat `{ rowIndex?, ...inputFields }`. Do **not** send `status`, `results`, or `errors` on create. |

Unknown keys and disallowed row properties (`status`, `results`, `errors`) are rejected by Joi validation with `409 MissingParameter`.

### Notes

- Never pass `status`, `results`, or `errors` inside `rows` when creating a batch; newly created rows always start in `pending` status.
- If `executor` is omitted, it is resolved from `batchConfiguration.executor` and normalized to `"queue"` or `"browser"`.
- After creation, call [Estimate Smart Batch cost](/smart-reports/estimate-smart-batch-cost) to preview credit charges and [Start a Smart Batch](/smart-reports/start-a-smart-batch) to begin processing.
- For bulk CSV, XLSX, or JSONL imports with dependency validation and optional immediate execution, use [Create a Smart Batch from a file](/smart-reports/create-smart-batch-from-file).
