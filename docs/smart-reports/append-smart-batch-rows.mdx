Append new input rows to an existing `SmartBatch` without overwriting existing rows or stored results. Both wrapped rows (`{ rowIndex?, inputData }`) and flat rows (`{ rowIndex?, ...inputFields }`) are accepted, and the server assigns sequential row indexes starting at `maxExisting + 1`.

Appending rows is forbidden while the batch is `"processing"` (`400 batch_append_not_allowed_while_processing`). If the batch was previously `"completed"` or `"failed"`, appending rows resets `status` to `"pending"` and clears `completedAt` so the new rows can run.

### Endpoint

```text
POST https://api.verifik.co/v2/smart-batches/{id}/rows/append
```

This endpoint is also reachable through the Smart-Agent proxy at `https://ai.verifik.co/v2/smart-batches/{id}/rows/append` using your own per-client `Authorization: Bearer <VERIFIK_JWT>`. Shared x402 execution is blocked with `403 Forbidden`.

### Headers

| Name            | Value                  | Description                              |
| --------------- | ---------------------- | ---------------------------------------- |
| `Content-Type`  | `application/json`     | Request payload format.                  |
| `Authorization` | `Bearer <VERIFIK_JWT>` | Client-scoped JWT (`authUser.clientId`). |

### Parameters

| Name | Type   | Required | Description |
| ---- | ------ | -------- | ----------- |
| `id` | string | Yes      | `SmartBatch` ObjectId to append rows to. |

### Body

| Name   | Type     | Required | Description |
| ------ | -------- | -------- | ----------- |
| `rows` | object[] | Yes      | Non-empty array (`min 1`) of wrapped (`{ rowIndex?, inputData }`) or flat (`{ rowIndex?, ...inputFields }`) input rows. Server assigns sequential `rowIndex = maxExisting + 1`. |

Unknown body keys or empty `rows` arrays are rejected by Joi validation with `409 MissingParameter`.

### Notes

- Appending rows does not run checks or spend credits; start the batch afterward with [Start a Smart Batch](/smart-reports/start-a-smart-batch).
- Any client-provided `rowIndex` is ignored in favor of sequential server-assigned numbering starting at `maxExisting + 1`.
- If the batch was `"completed"` or `"failed"`, its `status` resets to `"pending"` and `completedAt` is cleared.
