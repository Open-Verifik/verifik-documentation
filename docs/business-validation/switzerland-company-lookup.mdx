# Switzerland — Business & Corporate Registry Lookup (KYB)

The **Switzerland Business & Corporate Registry Lookup** verifies a legal entity against the official business registry. Send the corporate registration or tax identifier (UID / IDE / CHE) as `documentNumber`. Use it for KYB onboarding, vendor due diligence, and supplier screening.

`documentNumber` is required. `documentType` is optional. When you send it, use the identifier family (for example `UID`) so the registry can tell multi-number countries apart.

## What the registry returns

- Legal business name
- Registration status
- Incorporation date
- Tax or registration identifier
- Registered address

## Use cases

- Onboard a vendor or counterparty in Switzerland before the first payment.
- Confirm the legal name and registration status printed on a contract or invoice.
- Collect the incorporation date, tax identifier, and registered address for a KYB file.

---

## API Reference

### Endpoint

```http
GET https://api.verifik.co/v2/ch/company
```

Query the official business registry of Switzerland with `documentNumber` and an optional `documentType`. A successful payload includes the legal business name, registration status, incorporation date, the tax identifier (UID / IDE / CHE), and the registered address. Run it in a KYB onboarding or vendor due-diligence workflow. The sample below shows those fields. Live values, including the wording of `status`, come from the registry.

### Headers

| Name | Value | Description |
| :--- | :--- | :--- |
| Content-Type | `application/json` | Request payload format |
| Accept | `application/json` | Response format |
| Authorization | `Bearer <your_token>` | Client JWT authentication token |

### Parameters

| Name | Type | Required | Example | Description |
| :--- | :--- | :--- | :--- | :--- |
| `documentNumber` | string | **Yes** | `CHE107890123` | Official corporate registration number or tax ID (UID / IDE / CHE). |
| `documentType` | string | No | `UID` | Corporate document type or registry prefix. Accepted examples: `UID`, `IDE`, `CHE`. Omit it to send only the official number. |

### Notes

- **Identifier format.** The UID (IDE / CHE) is the prefix CHE plus 9 digits. Printed forms use CHE-123.456.789. You can send CHE and the 9 digits with or without the dots and hyphens.
- Corporate document type or registry prefix. Accepted examples: `UID`, `IDE`, `CHE`. Omit it to send only the official number.
- The status label in the sample illustrates the field. The live registry returns its own label, which may be a local-language status.
- Send `documentNumber` and, when you need to name the identifier family, `documentType`. Those are the client parameters for this route.
- The JSON sample is an illustration of the fields above. A live call returns the registry record for the identifier you send.

## Sandbox

With the account in sandbox mode, the same parameters exercise this route. The table describes the response documented for each case.

| Scenario | Parameters | Result |
| :--- | :--- | :--- |
| **Identifier on file** | `documentType: "UID"`, `documentNumber: "CHE107890123"` | 200 with legal name, status, identifier, and address or identity attributes when the source holds the number. |
| **Missing documentNumber** | Omit `documentNumber` | 409 `MissingParameter` when `documentNumber` is omitted. |
| **Unknown number** | `documentNumber: "000000000"` | 404 `NotFound` when the registry has no record for that number. |

401 when the bearer token is missing or rejected.
