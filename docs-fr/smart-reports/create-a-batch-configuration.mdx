Créez une `BatchConfiguration` personnalisée sur votre compte client authentifié. Définissez le `country` cible, les `steps` de vérification ordonnées référençant des identifiants `AppFeature` du catalogue, les formats d'entrée/sortie facultatifs, les paramètres de réessai, un graphe visuel `visitaFlow` ainsi que les notifications de fin d'exécution.

La création d'une configuration n'exécute aucune vérification et ne consomme pas de crédits. Notez que ce point de terminaison renvoie HTTP `200` (et non `201`) avec la configuration enregistrée dans `data`. La validation du schéma est gérée directement par Mongoose : des champs invalides ou manquants renvoient donc `422 UnprocessableEntity`.

### Point de terminaison

```
POST https://api.verifik.co/v2/batch-configurations
```

Également accessible via le proxy Smart-Agent à l'adresse `https://ai.verifik.co/v2/batch-configurations` avec votre propre en-tête par client `Authorization: Bearer <VERIFIK_JWT>`. L'exécution partagée x402 est bloquée avec `403 Forbidden`.

### En-têtes

| Nom | Valeur |
| ---- | ----- |
| Content-Type | `application/json` |
| Authorization | `Bearer <VERIFIK_JWT>` |

Le jeton doit être un **JWT client**. Des identifiants manquants ou invalides renvoient `401 Unauthorized`.

### Corps de la requête

| Nom | Type | Requis | Description |
| ---- | ---- | -------- | ----------- |
| `name` | string | Oui | Nom affiché de la configuration. Nettoyé des espaces, `150` caractères maximum. |
| `country` | string | Oui | Portée géographique (pays) de la configuration. Nettoyé des espaces et converti en majuscules par le serveur (par exemple, `CO`). |
| `steps` | object[] | Oui | Tableau ordonné d'objets d'étapes de vérification (voir les champs de `steps[]` ci-dessous). |
| `description` | string | Non | Résumé facultatif du workflow. `800` caractères maximum. |
| `executor` | string | Non | Cible d'exécution : `queue`, `featureRunner` ou `browser`. Par défaut `featureRunner` (enregistré comme `browser`, tandis que le runner headless s'exécute via `FeatureRunner`). |
| `inputFormat` | string | Non | Format d'entrée par défaut : `csv`, `jsonl` ou `xlsx`. Par défaut `csv`. |
| `outputFormat` | string | Non | Format de sortie par défaut : `csv`, `jsonl` ou `xlsx`. Par défaut `csv`. |
| `mergeStrategy` | string | Non | Stratégie d'exécution des étapes : `sequential`, `parallel-independent` ou `parallel-with-fallback`. Par défaut `sequential`. |
| `notification` | object | Non | Paramètres de notification de fin (`webhookUrl` et `emailOnCompletion`). Voir les champs de `notification` ci-dessous. |
| `scheduleExpression` | string | Non | Expression de planification facultative pour les exécutions automatisées. |
| `preferredReportTemplate` | string | Non | ObjectId `SmartReportTemplate` lié comme modèle de rapport par défaut pour les lots de cette configuration. |
| `visitaFlow` | object | Non | Graphe visuel de nœuds définissant le chaînage des étapes. Tous les espaces réservés `{{results.N.field}}` sont exclus des entrées manuelles dans le schéma d'entrée dérivé. |
| `isActive` | boolean | Non | Indique si la configuration est active. Par défaut `true`. |

#### Champs de l'objet `steps[]`

| Nom | Type | Requis | Description |
| ---- | ---- | -------- | ----------- |
| `appFeature` | string | Oui | ObjectId `AppFeature` à exécuter pour cette étape. |
| `sequence` | number | Oui | Ordre d'exécution de l'étape indexé à partir de 1 (`>= 1`). |
| `enabled` | boolean | Non | Indique si cette étape s'exécute pendant le traitement du lot. Par défaut `true`. |
| `parameterDefaults` | object | Non | Valeurs de paramètres statiques ou expressions `{{results.N.field}}` rattachées à cette étape. Par défaut `{}`. |
| `queryMode` | string | Non | Sélecteur facultatif de groupe de dépendances lorsque la fonctionnalité prend en charge plusieurs modes de consultation. |
| `inputFieldMapping` | object | Non | Mappe les noms de colonnes d'entrée vers les noms de paramètres de l'API (`inputColumn -> apiParam`). Par défaut `{}`. |
| `outputFieldsToKeep` | string[] | Non | Sous-ensemble de champs de sortie à conserver dans les résultats tabulaires. Par défaut `[]`. |
| `maxRetries` | number | Non | Nombre maximal de tentatives de réessai en cas d'échec transitoire de l'étape (`>= 0`). Par défaut `3`. |
| `retryDelayBaseSeconds` | number | Non | Délai de backoff de base en secondes (`>= 1`). Par défaut `4`. |
| `timeoutSeconds` | number | Non | Délai d'expiration d'exécution de l'étape en secondes (`>= 5`). Par défaut `30`. |

#### Champs de l'objet `notification`

| Nom | Type | Requis | Description |
| ---- | ---- | -------- | ----------- |
| `webhookUrl` | string | Non | Point de terminaison HTTPS à notifier à la fin du lot. Fournir `webhookUrl` synchronise automatiquement un webhook Verifik actif pour votre client. |
| `emailOnCompletion` | string[] | Non | Liste des adresses e-mail destinataires à notifier lorsqu'un lot se termine. |

### Notes

- En cas de succès, la réponse renvoie HTTP **`200`** (et non `201`) avec le document créé dans `data`.
- Ce point de terminaison ne dispose pas de middleware Joi ; la validation de schéma Mongoose vérifie les champs obligatoires et les contraintes numériques, et renvoie `422 UnprocessableEntity` en cas d'échec.
- Lorsque `executor` vaut `"featureRunner"` (la valeur par défaut), le serveur enregistre `"browser"` sur le document de configuration tandis que le runner headless continue de s'exécuter via `FeatureRunner`.
- La définition de `notification.webhookUrl` crée ou synchronise automatiquement un webhook Verifik actif pour votre client.
- Appelez ensuite [Récupérer le schéma d'entrée d'une configuration](/verifik-fr/smart-reports/retrieve-configuration-input-schema) pour inspecter les champs dérivés et `exampleInput` avant d'exécuter un rapport.
