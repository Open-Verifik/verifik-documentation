Mettez à jour une `BatchConfiguration` existante détenue par votre compte client. Envoyez uniquement les champs que vous souhaitez modifier ; les champs omis conservent leurs valeurs actuelles.

Lorsque `steps` est fourni, le serveur normalise les valeurs `sequence` manquantes à `index + 1` et borne `retryDelayBaseSeconds` (`>= 1`) ainsi que `timeoutSeconds` (`>= 5`). La mise à jour de `notification` synchronise automatiquement le webhook Verifik associé, et la modification de `executor` propage le nouvel exécuteur aux lots enfants non terminaux. La mise à jour d'une configuration n'exécute aucune consultation et ne consomme pas de crédits.

### Point de terminaison

```
PUT https://api.verifik.co/v2/batch-configurations/{id}
```

Également accessible via le proxy Smart-Agent à l'adresse `https://ai.verifik.co/v2/batch-configurations/{id}` avec votre propre en-tête par client `Authorization: Bearer <VERIFIK_JWT>`. L'exécution partagée x402 est bloquée avec `403 Forbidden`.

### En-têtes

| Nom | Valeur |
| ---- | ----- |
| Content-Type | `application/json` |
| Authorization | `Bearer <VERIFIK_JWT>` |

Le jeton doit être un **JWT client**. Des identifiants manquants ou invalides renvoient `401 Unauthorized`.

### Paramètres

| Nom | Type | Requis | Description |
| ---- | ---- | -------- | ----------- |
| `id` | string | Oui | ObjectId `BatchConfiguration` à mettre à jour. |

### Corps de la requête

Tous les champs du corps sont facultatifs. N'incluez que les propriétés à mettre à jour.

| Nom | Type | Requis | Description |
| ---- | ---- | -------- | ----------- |
| `name` | string | Non | Nom affiché de la configuration. Nettoyé des espaces, `150` caractères maximum. |
| `description` | string | Non | Résumé facultatif du workflow. `800` caractères maximum. |
| `country` | string | Non | Portée géographique (pays). Nettoyé des espaces et converti en majuscules par le serveur. |
| `steps` | object[] | Non | Remplace le tableau ordonné d'étapes. Une valeur `sequence` manquante prend par défaut `index + 1` ; `retryDelayBaseSeconds` est borné à `>= 1` et `timeoutSeconds` à `>= 5`. |
| `inputFormat` | string | Non | Format d'entrée par défaut : `csv`, `jsonl` ou `xlsx`. |
| `outputFormat` | string | Non | Format de sortie par défaut : `csv`, `jsonl` ou `xlsx`. |
| `mergeStrategy` | string | Non | Stratégie d'exécution des étapes : `sequential`, `parallel-independent` ou `parallel-with-fallback`. |
| `notification` | object | Non | Paramètres de notification de fin (`webhookUrl` et `emailOnCompletion`). Synchronise automatiquement un webhook Verifik actif lorsque `webhookUrl` est défini. |
| `scheduleExpression` | string | Non | Expression de planification pour les exécutions automatisées. |
| `preferredReportTemplate` | string | Non | ObjectId `SmartReportTemplate` lié à cette configuration. |
| `visitaFlow` | object | Non | Graphe visuel de nœuds définissant le chaînage des étapes (les expressions `{{results.N.field}}` sont exclues des entrées manuelles dans le schéma d'entrée dérivé). |
| `isActive` | boolean | Non | Indique si la configuration est active. |
| `executor` | string | Non | Cible d'exécution : `queue`, `featureRunner` ou `browser` (`featureRunner` est enregistré comme `browser`). Synchronise les lots enfants non terminaux en cas de modification. |

### Notes

- L'envoi de `steps` remplace l'intégralité du tableau `steps` de la configuration ; il ne modifie pas les étapes individuellement sur place.
- Les valeurs `sequence` manquantes dans `steps` sont normalisées à `index + 1`, `retryDelayBaseSeconds` est borné à `>= 1` et `timeoutSeconds` à `>= 5`.
- La modification de `executor` synchronise tous les lots enfants non terminaux appartenant à cette configuration.
- Les identifiants manquants ou appartenant à un autre client renvoient `404` (`not_found`), tandis que les erreurs de validation de schéma Mongoose renvoient `422` (`UnprocessableEntity`).
