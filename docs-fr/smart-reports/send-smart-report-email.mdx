Livrez un `SmartReport` par e-mail avec les rapports PDF en pièce jointe. Vous pouvez laisser Verifik générer le PDF pour une seule ligne (`rowIndex`) ou pour toutes les lignes (`sendAll: true`, jusqu'à `50` lignes), ou fournir des payloads pré-rendus `printHtml`, `pdfBase64` ou `pdfFiles`.

L'envoi d'un e-mail enregistre `emailDelivery` sur le document `SmartReport` et émet soit `smart_batch_report_sent` en cas de succès, soit `smart_batch_report_delivery_failed` en cas d'échec de livraison.

### Point de terminaison

```
POST https://api.verifik.co/v2/smart-reports/{id}/send-email
```

Ce point de terminaison accepte des payloads JSON jusqu'à **64 Mo**. Il est également accessible via le proxy Smart-Agent à l'adresse `https://ai.verifik.co/v2/smart-reports/{id}/send-email` en utilisant votre propre en-tête par client `Authorization: Bearer <VERIFIK_JWT>`. L'exécution partagée x402 est bloquée avec `403 Forbidden`.

### En-têtes

| Nom             | Valeur                 | Description                                                |
| --------------- | ---------------------- | ---------------------------------------------------------- |
| `Content-Type`  | `application/json`     | Format du payload de la requête (limite de 64 Mo).         |
| `Authorization` | `Bearer <VERIFIK_JWT>` | JWT limité au client (`authUser.clientId`).                |

### Paramètres

| Nom  | Type   | Requis  | Description |
| ---- | ------ | ------- | ----------- |
| `id` | string | **Oui** | ObjectId du `SmartReport`. |

### Corps de la requête

| Nom          | Type     | Requis  | Description |
| ------------ | -------- | ------- | ----------- |
| `recipients` | string[] | **Oui** | Tableau d'adresses e-mail de destinataires valides (minimum `1`). |
| `subject`    | string   | Non     | Objet d'e-mail personnalisé. |
| `language`   | string   | Non     | Langue du texte de l'e-mail : `"en"` ou `"es"`. Défaut `"es"`. |
| `rowIndex`   | number   | Non     | Index de ligne basé sur zéro à générer et joindre lorsque `sendAll` n'est pas activé. |
| `sendAll`    | boolean  | Non     | Lorsqu'il vaut `true`, envoie jusqu'à `50` lignes (`MAX_SEND_ALL_ROWS`), en joignant 1 PDF par ligne lorsque le lot contient plus d'une ligne. |
| `engine`     | string   | Non     | Moteur de rendu PDF : `"pdfkit"` ou `"puppeteer"`. |
| `printHtml`  | string   | Non     | Chaîne HTML pré-rendue (max `64000000` caractères) à convertir et joindre. |
| `pdfBase64`  | string   | Non     | Chaîne PDF encodée en base64 pré-rendue (max `64000000` caractères) à joindre directement. |
| `pdfFiles`   | object[] | Non     | Tableau contenant jusqu'à `200` objets pièces jointes (`{ filename, pdfBase64 }`), où `filename` (max `80` caractères) et `pdfBase64` (max `64000000` caractères) sont requis. |

#### Règles des pièces jointes et de l'envoi par lot

- **Plafond `sendAll`** : L'envoi de toutes les lignes d'un lot prend en charge jusqu'à `50` lignes (`MAX_SEND_ALL_ROWS`). Dépasser 50 lignes échoue avec `409 Conflict` (`send_all_limit`). Lorsqu'un lot contient plus d'une ligne, chaque ligne est jointe dans son propre fichier PDF.
- **Payloads pré-rendus** : Fournissez `pdfFiles` (jusqu'à `200` éléments), `pdfBase64` ou `printHtml` lorsque votre intégration a déjà effectué le rendu de pièces jointes personnalisées. Des données PDF corrompues renvoient `500` (`invalid_pdf`), et les requêtes ne résolvant aucune pièce jointe renvoient `409 Conflict` (`no_pdf_attachments`).
- **Réponse de résultat de livraison** : Si le transport d'e-mail échoue après la validation et la préparation réussie du PDF, le point de terminaison renvoie HTTP `200 OK` avec `"success": false`, `"messageId": null` et un champ `"error"`, tout en enregistrant `emailDelivery` et en émettant `smart_batch_report_delivery_failed`.

#### Codes d'erreur

| Statut | Code / Type d'erreur | Cause |
| ------ | -------------------- | ----- |
| `401` | `Unauthorized` | JWT manquant ou invalide. |
| `403` | `Forbidden` | Exécution partagée x402 tentée ; utilisez votre propre JWT par client. |
| `404` | `not_found` | L'ID du rapport n'existe pas ou appartient à un autre client. |
| `404` | `template_not_found` | Le modèle lié est introuvable. |
| `409` | `MissingParameter` | La validation Joi a échoué (par exemple, `recipients` manquant ou invalide). |
| `409` | `send_all_limit` | `sendAll: true` a été demandé sur un lot de plus de `50` lignes (`MAX_SEND_ALL_ROWS`). |
| `409` | `no_pdf_attachments` | Aucune pièce jointe PDF n'a pu être résolue ou générée pour la requête. |
| `409` | `row_not_found` | Le `rowIndex` demandé n'existe pas dans le lot. |
| `422` | `UnprocessableEntity` | Erreur de validation Mongoose. |
| `500` | `invalid_pdf` | Le payload `pdfBase64` ou `pdfFiles` fourni n'est pas un PDF valide. |

### Intégration Webhooks et MCP

- **Webhooks** : Émet automatiquement `smart_batch_report_sent` lorsque l'envoi réussit ou `smart_batch_report_delivery_failed` lorsqu'il échoue, et enregistre `emailDelivery` sur le `SmartReport`. Consultez [Webhooks SmartReports](/verifik-fr/resources/smart-reports-webhooks).
- **Équivalent MCP** : Les agents IA peuvent envoyer des rapports par e-mail via l'outil MCP `smart_report_send_email`. Consultez [MCP et Agents IA](/verifik-fr/smart-reports/mcp-and-ai-agents).

### Notes

- Vérifiez toujours `success` dans le corps `200 OK`, car les erreurs de transport d'e-mail renvoient `success: false` avec `messageId: null` et `error` plutôt qu'un code de statut différent de 200.
- Si vous souhaitez exécuter les étapes de vérification, générer les PDF et envoyer l'e-mail en un seul appel, utilisez [Exécuter un Smart Report](/verifik-fr/smart-reports/run-a-smart-report).
