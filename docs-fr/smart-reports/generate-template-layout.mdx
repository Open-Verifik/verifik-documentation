Générez, ajoutez ou modifiez des définitions structurées `ReportSection` à partir d'un `prompt` en langage naturel via Gemini (température `0.2`). Transmettez des données de vérification d'exemple dans `previewData` afin que le modèle aligne les liaisons `dataPath` des sections et les dispositions de colonnes avec la structure réelle de votre payload.

Dans les générateurs de rapports headless et les pipelines d'agents IA, utilisez ce point de terminaison pour échafauder des mises en page complètes (`"create"`), ajouter des sections supplémentaires à un modèle existant (`"append"`) ou affiner une seule section (`"edit"`) sans écrire le JSON des sections manuellement. Associez cet appel à [Prévisualiser le HTML d'un modèle](/verifik-fr/smart-reports/preview-template-html) pour inspecter le rendu avant d'enregistrer avec [Créer un modèle de rapport](/verifik-fr/smart-reports/create-a-report-template) ou [Mettre à jour un modèle de rapport](/verifik-fr/smart-reports/update-a-report-template).

### Point de terminaison

```
POST https://api.verifik.co/v2/smart-report-templates/generate-layout
```

Le proxy Smart-Agent (`https://ai.verifik.co`) expose les mêmes chemins `/v2/...` et exige votre propre en-tête `Authorization: Bearer <VERIFIK_JWT>`.

### En-têtes

| Nom           | Valeur                 |
| ------------- | ---------------------- |
| Content-Type  | `application/json`     |
| Accept        | `application/json`     |
| Authorization | `Bearer <VERIFIK_JWT>` |

### Corps de la requête

| Nom               | Type          | Requis | Description                                                                                                                               |
| ----------------- | ------------- | ------ | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `prompt`          | string        | Oui    | Instructions en langage naturel décrivant la mise en page à créer, les sections à ajouter ou les modifications à appliquer en mode édition. |
| `mode`            | string        | Oui    | Mode de génération : `"create"`, `"edit"` ou `"append"`.                                                                                  |
| `previewData`     | object        | Non    | JSON d'exemple de vérification (par exemple `inputData`, `results`, `batchName`) utilisé pour ancrer les expressions `dataPath` et colonnes générées. |
| `currentSections` | object[]      | Non    | Tableau `ReportSection` existant. Recommandé en mode `"append"` afin que les nouvelles sections poursuivent la séquence `order` existante. |
| `selectedSection` | object / null | Non    | Objet `ReportSection` cible à modifier lorsque `mode` vaut `"edit"`. S'il vaut `null` ou est omis en mode `"edit"`, le comportement bascule sur `"create"`. |

### Notes

- Les modes `"create"` et `"append"` renvoient `{ "data": [ ...ReportSection ] }` (un tableau), tandis que le mode `"edit"` avec un `selectedSection` non nul renvoie `{ "data": { ...ReportSection } }` (un objet unique).
- Appeler `"edit"` avec `selectedSection: null` ou en omettant `selectedSection` revient au mode `"create"` et renvoie un tableau.
- Ce point de terminaison n'écrit pas en base de données. Transmettez les `sections` renvoyées à [Prévisualiser le HTML d'un modèle](/verifik-fr/smart-reports/preview-template-html) pour inspecter le HTML ou à [Créer un modèle de rapport](/verifik-fr/smart-reports/create-a-report-template) pour l'enregistrer.
