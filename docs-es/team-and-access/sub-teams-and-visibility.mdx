# Sub-Equipos, Jerarquía y Visibilidad Acotada

Los Sub-Equipos permiten que organizaciones con múltiples países, marcas o departamentos compartan una sola billetera Verifik manteniendo aislamiento de datos PII, límites de gasto mensual, bloqueo estricto de Centros de Costo (CECO) y API Keys acotadas por unidad.

---

## Modelo de Sub-Equipo y Jerarquía (`parentTeam`)

Cada Sub-Equipo puede apuntar opcionalmente a un **`parentTeam`** para modelar estructuras regionales y nacionales sin duplicar cuentas:

```text
Workspace (Owner / Admin Global)
 ├── LATAM Regional (parentTeam: null, team_manager ve todos sus hijos)
 │    ├── Colombia Ops (parentTeam: LATAM Regional, CECO: CO-OPS, $1,500/mes)
 │    └── México Ops   (parentTeam: LATAM Regional, CECO: MX-OPS, $2,000/mes)
 └── Plantillas Compartidas (visibility: "workspace", sin resultados con PII)
```

- **Detección de ciclos**: Al crear o actualizar un Sub-Equipo se rechazan auto-referencias y ciclos transitivos (`A -> B -> A`).
- **Eliminación segura (`DELETE /v2/teams/:id`)**:
  - Los sub-equipos hijos directos se reasignan automáticamente al `parentTeam` del equipo eliminado (`null` si era raíz).
  - Se limpia automáticamente cualquier referencia residual en `Staff.additionalTeams`.
  - Puedes enviar `reassignToTeamId` para migrar miembros principales y recursos del equipo de forma atómica.

---

## Membresía Principal (`team`) vs. Secundarias (`additionalTeams`)

Verifik distingue el **equipo principal** de las **membresías secundarias**:

- **`team`** *(equipo principal)*: Ancla única para atribuir nuevas creaciones (reportes, lotes, proyectos y consultas) generadas desde el portal.
- **`additionalTeams`** *(arreglo secundario, hasta 20 equipos)*: Concede visibilidad de lectura (y gestión de sub-árbol para `team_manager`) sobre unidades adicionales sin duplicar cuentas de Staff.

El conjunto efectivo visible (`teamIds`) de cada usuario es la unión de:

`team primario` ∪ `additionalTeams` ∪ `todos los descendientes recursivos vía parentTeam`

## Presupuestos Mensuales, Límites por Endpoint y Boosts

Cada Sub-Equipo contabiliza el consumo por mes UTC y valida los topes antes de llamar a fuentes externas:

| Campo | Propósito | Comportamiento |
| --- | --- | --- |
| `status` | `"active"` o `"paused"` | Si está en `"paused"`, rechaza ejecuciones con `403 team_paused` |
| `monthlyBudget` | Tope mensual en USD o `null` (ilimitado) | Validado en tiempo real antes de consultas y SmartReports |
| `budgetEnforcement` | `"hard"` (defecto) o `"soft"` | `"hard"` bloquea al alcanzar 100% (`403 team_budget_exceeded`); `"soft"` permite continuar emitiendo alertas |
| `featureBudgets` | Lista `{ endpointPrefix, monthlyLimit }` | Limita endpoints costosos específicos (ej. `/v2/co/runt/vehiculo`), retornando `403 team_feature_budget_exceeded` |

### Aumentos Temporales o Recurrentes (`POST /v2/teams/:id/boost`)

```bash
curl -X POST https://api.verifik.co/v2/teams/<TEAM_ID>/boost \
  -H "Authorization: Bearer $MANAGER_JWT" \
  -H "Content-Type: application/json" \
  -d '{
    "amount": 250,
    "mode": "current_month",
    "reason": "Pico de alta de conductores de fin de mes"
  }'
```

## Bloqueo de Centros de Costo (CECO)

- **`defaultCostCenter`**: Se asigna automáticamente cuando el usuario o API Key omite el header `x-cost-center`.
- **`allowedCostCenters`**: Lista blanca de Centros de Costo autorizados para ese equipo.
- **`enforceCostCenter: true`**: Rechaza cualquier solicitud cuyo `x-cost-center` quede fuera de `[defaultCostCenter, ...allowedCostCenters]` con `400 cost_center_not_allowed_for_team` antes de consumir créditos.

## Visibilidad Acotada (`teamScopedVisibility`) y Plantillas Compartidas

Activa el aislamiento estricto en **Equipos y Acceso → Política de Acceso** (o vía `PUT /v2/client-settings/:id` con `staffAccessPolicy.teamScopedVisibility: true`).

Sin el permiso `team.readAll`, los usuarios quedan filtrados a sus `teamIds` efectivos en estas **11 colecciones**:

1. `SmartReport`
2. `SmartBatch`
3. `BatchConfiguration`
4. `SmartReportTemplate`
5. `Project`
6. `ProjectFlow`
7. `AppRegistration`
8. `DocumentValidation`
9. `BiometricValidation`
10. `APIRequest`
11. `StaffAuditLog`

### Plantillas Compartidas (`visibility: "workspace"`)

Los recursos de diseño reutilizable (`SmartReportTemplate`, `BatchConfiguration`, `Project` y `ProjectFlow`) aceptan **`visibility: "workspace"`**. Así, un equipo central (por ejemplo `report_builder`) publica un diseño único visible para todos los países, mientras que **las ejecuciones, PDFs y registros con PII permanecen estrictamente aislados** en el equipo que los ejecutó. Usa `POST /v2/teams/:id/assign` para asignar activos existentes o marcar plantillas compartidas.

## API Keys de Sub-Equipo (`POST /v2/teams/:id/api-keys`)

<Tabs groupId="http-js">
<TabItem value="curl" label="cURL" default>

```bash
# 1. Generar API Key vinculada al Sub-Equipo Colombia
curl -X POST https://api.verifik.co/v2/teams/<CO_TEAM_ID>/api-keys \
  -H "Authorization: Bearer $OWNER_OR_ADMIN_JWT" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "worker-kyc-colombia",
    "expiresIn": "1y"
  }'

# 2. Ejecutar SmartReport usando esa Team API Key
curl -X POST https://api.verifik.co/v2/smart-reports/run \
  -H "Authorization: Bearer $CO_TEAM_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "systemKey": "co.citizen.comprehensive",
    "inputs": { "documentType": "CC", "documentNumber": "123456789" },
    "mode": "sync",
    "generatePdf": true
  }'
```

</TabItem>
