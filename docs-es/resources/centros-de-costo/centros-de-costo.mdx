# Centros de costo

Un centro de costo es una etiqueta para una parte de tu negocio, como la operación de un país o un equipo. Cada solicitud de tu cuenta puede llevar uno, y la [API de uso](/verifik-es/resources/uso) agrupa totales y exportaciones CSV por centro de costo. Administrar centros de costo no consume créditos.

También puedes administrarlos en el panel de cliente, en **Configuración → Centros de Costo**.

## Vincula los centros de costo a tu consumo {#vincular-centros-de-costo}

Esto aplica a las solicitudes que hagas después de configurarlo. Las solicitudes ya guardadas conservan el centro de costo que tenían.

1. **Crea el centro de costo.** En el panel, abre **Configuración → Centros de Costo** y agrega uno, o llama a [`POST /v2/cost-centers`](/verifik-es/resources/centros-de-costo/crear-un-centro-de-costo). Conserva el `code`, por ejemplo `SPAIN-OPS`.
2. **Elige cómo lo reciben las llamadas siguientes.**
   - **En cada llamada:** envía el header `x-cost-center` con el código o el id.
   - **En cada llamada que use un token:** abre **Configuración → Clave API**, elige ese proyecto y guarda un valor por defecto. El mismo cambio es `PUT /v2/projects/{id}` con `{ "costCenter": "<id>" }`. Envía `null` para quitarlo.
   - **Por país:** deja exactamente un centro de costo activo para ese código ISO-2. Una llamada a `/v2/es/...` usa entonces el centro de España, sin header.
3. **Haz una llamada normal de datos.** Si envías el header, tiene prioridad sobre el valor del proyecto y sobre la regla del país.

```bash
curl "https://api.verifik.co/v2/co/cedula?documentType=CC&documentNumber=123456789" \
  -H "Authorization: Bearer $VERIFIK_TOKEN" \
  -H "x-cost-center: SPAIN-OPS"
```

4. **Revisa el consumo.** En el panel, abre **Configuración → Reporte de Uso** y agrupa o filtra por centro de costo. El mismo corte es `GET /v2/usage?groupBy=costCenter` en la [API de uso](/verifik-es/resources/uso). Las solicitudes sin centro de costo quedan en el grupo vacío.
5. **Un cambio posterior no reescribe las solicitudes anteriores.** Actualizar el valor por defecto del proyecto, o desactivar un centro, solo afecta las llamadas hechas después. El historial ya marcado se queda como estaba.

## Cómo se asigna el centro de costo a una solicitud

Verifik revisa estas reglas en orden y usa la primera que aplique:

1. **El header `x-cost-center`.** Envía el código o el id en cualquier solicitud de la API de datos. Si el valor no coincide con un centro de costo activo de tu cuenta, la solicitud falla con `400` antes de cobrar créditos.
2. **El valor por defecto del proyecto del token.** Defínelo con `PUT /v2/projects/{id}` y `{ "costCenter": "<id>" }` (envía `null` para quitarlo). Un id que no sea un centro de costo activo de tu cuenta devuelve `409` con `invalid_cost_center`.
3. **El país del endpoint.** Una solicitud a `/v2/es/...` usa tu centro de costo de `ES` cuando tienes exactamente un centro activo para ese país.

Si ninguna regla aplica, la solicitud queda sin centro de costo y aparece como `null` en los reportes de uso.

```bash
curl "https://api.verifik.co/v2/co/cedula?documentType=CC&documentNumber=123456789" \
  -H "Authorization: Bearer $VERIFIK_TOKEN" \
  -H "x-cost-center: SPAIN-OPS"
```

```json
{
	"code": "BadRequest",
	"message": "x-cost-center does not match an active cost center on this account"
}
```
